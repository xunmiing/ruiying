# 瑞赢 0.1 HTML 原型全局交互规范

> 适用范围：瑞赢 0.1 的 PC 与 H5 HTML 评审原型。
> 文档职责：统一页面契约、页面说明、黄色标签、录入区域及标准 PC 表格列表的呈现方式；不定义业务字段、权限或服务端规则。
> 状态：2026-10-14 确认的规范；现有页面尚未按本文统一改造。

## 1. 依据与边界

1. 业务事实以当前 `assets/`、0.1 总 PRD 和对应模块 PRD 为准。本文只规定如何在 HTML 原型中呈现这些事实，不用原型现状反推业务规则。
2. PC 与 H5 可以采用不同布局，但相同业务对象的字段含义、选项、必填条件和联动结果应一致。若正式设计允许端侧差异，以对应 PRD 为准。
3. 原型要能走查页面状态和关键操作。黄色标签及页面说明仅用于评审解释，不能表示已实现正式鉴权、唯一性、并发控制或数据持久化保证。
4. 本文与旧页面说明或旧原型文字不一致时，先核对当前 PRD 和产品负责人已确认的决定；发现业务事实冲突时记录差异，不自行改写业务规则。

## 2. 信息呈现分层

| 层次 | 展示内容 | 位置与方式 |
| --- | --- | --- |
| 实际交互 | 字段、控件、必填标识、选项、显隐结果、可操作状态和校验错误 | 直接显示在页面或表单中，供用户完成操作 |
| 就近规则解释 | 不属于最终实现界面的提示、评审说明，以及字段或操作的特殊规则解释 | 放在相关字段、字段组或操作旁的黄色短标签中，点击后查看 |
| 完整页面说明 | 页面契约、页面功能、需要说明的页面级规则、录入字段要求、标准 PC 表格列表的筛选项和字段表，以及确有差异的角色权限 | 放在统一的“页面说明”入口中，默认不占据业务操作区域 |

逐条判断页面提示：无助于理解当前操作、重复按钮或字段本身、只描述操作过程的提示直接删除；对理解特殊业务判断或原型边界确有价值的提示，改为相关位置的黄色标签，完整口径放入页面说明。真实状态、结果数、必填与校验反馈仍直接显示，不把操作所需信息藏入标签。

## 3. 黄色标签

1. 标签使用黄色样式，显示序号和几个字的短标题；点击后在标签附近打开可关闭的说明浮窗。
2. 标签靠近它解释的字段、字段组或操作。同一规则只设置一个入口，不在页面多处重复解释。
3. 浮窗写清触发条件与结果，避免只重复字段名称。字段选项或上游值变化时，页面应直接呈现相应的显隐与选项变化；标签只解释原因和边界。
4. 评审说明、原型能力边界、正式服务端才会执行的校验说明放入标签或页面说明，不作为常驻业务提示。
5. 必填标识、当前错误及用户必须据此完成操作的状态反馈直接呈现，不藏入黄色标签。

例如，选择“自然人客户”后，相关字段应按规则直接隐藏；客户类型为什么影响采集范围，可由客户类型附近的黄色标签解释。各类型的长篇介绍不常驻显示在表单下方。

## 4. 页面说明

1. 页面说明写本页实际涉及的功能、字段与规则，不机械复制通用制度，也不重复页面上已经能直接看出的内容。
2. 角色权限只在本页的可进入范围、可见数据、可指定对象或可执行操作确有差异时说明，并仅描述与本页有关的差异。字段填写逻辑不因角色变化时，不放三角色权限表。
3. 录入页在页面说明中设置完整的“字段要求”表；字段旁仅对特殊显隐、联动或校验规则设置黄色标签，不为每个字段重复放一份要求。
4. 页面说明与黄色标签使用同一业务口径。表格负责完整核对，黄色标签负责在操作位置快速找到特殊规则。
5. 页面说明的页面名称下直接展示契约信息，不单独显示“页面契约”标题；随后展示本页功能、规则及字段要求。页面正文不另放“本页契约”卡片，页面说明底部也不重复展示契约或“页面编号、依据与覆盖范围见上方页面说明”等占位文字。
6. 页面说明面板顶部使用当前页面名称作为标题；关闭按钮与标题固定在面板顶部，滚动长说明时仍可见、可操作。侧边打开入口仍标为“页面说明”。

### 4.1 契约信息呈现

1. “页面编号、适用端、依据”使用一个三列表格展示，表头按此顺序排列；表格内容分别取本页契约编号、PC／H5 端别和对应 PRD 章节。以 `assets/js/page-manifest.js` 定位页面与契约的映射，再核对当前 PRD。覆盖范围与验收项放在表格下方，仍属于同一页面契约区。

   | 页面编号 | 适用端 | 依据 |
   | --- | --- | --- |
   | 与当前页面清单一致 | PC 或 H5 | 对应 PRD 章节 |

   三列采用紧凑的元数据样式：浅色小字列名在上、加粗内容在下，整体仅用上下分隔线区分页面内容，不画单元格边框；窄屏允许依据换行，但不截断编号或章节。

2. 覆盖范围概括本页承载的主要视图、状态或关键操作，不把页面功能说明全文复制到契约区。
3. 验收项列出与本页直接相关的需求验收标准编号和专项测试用例编号，用于从原型追溯到验收依据；它不是表单字段，也不表示 HTML 原型已实现正式服务端保证。编号应与当前 PRD、测试用例及页面清单逐项核对；发现错配时先修正引用或记录差异，不沿用无关编号。
4. PC 与 H5 同一页面契约可共用页面编号和验收项，但“适用端”应显示当前端别；如果两端覆盖范围或依据不同，分别按实际页面填写。

## 5. 新增／编辑等录入区域

适用于独立新增／编辑页，也适用于详情页中承担录入任务的弹窗、抽屉和局部表单。以下规则只约束录入交互，不改变各模块已确认的字段与业务流程。

### 5.1 表单正文

- 删除选项逐项介绍、保存后会发生什么等不影响当前填写的常驻说明；有评审价值的内容按第 3 节转入黄色标签。
- 保留字段名称、必填标识、控件、当前可选项、实际显隐和必要的即时反馈。
- 控件的默认值、选项来源、条件必填、显隐联动及特殊校验以当前 PRD 为准。页面说明应解释这些规则，原型应呈现能走查的交互结果。

### 5.2 字段要求表

每个录入页在页面说明中按表单分组列出所有可录入字段，统一使用下列四列：

| 字段名称 | 字段类型 | 是否必填 | 备注 |
| --- | --- | --- | --- |
| 与页面字段标签一致 | 文本框、文本域、单选、下拉选择、日期选择等实际控件 | 是、否，或写明条件必填 | 按需写选项范围及来源、默认值、特殊逻辑、校验要求、与其他字段的显隐或选项联动 |

表格中的“是否必填”应对应当前场景；存在类型或状态条件时写明触发条件，不只填“是／否”。尚未确认的选项或字段规则应明确标为待确认，不由原型自行补全。

### 5.3 顶部与操作按钮

- 录入页的标题区与主要操作按钮在页面向下滚动时保持可见；表单内容可以继续滚动。PC 已固定的全局顶栏与录入页固定区应正确叠放，不互相遮挡。
- H5 沿用移动端布局，主要操作在顶部持续可见时，不应遮挡当前输入字段；键盘弹出、页面说明及黄色标签浮窗打开时也应可操作。
- 固定区域只承载本页主要操作，避免把长说明或大量次要按钮固定在顶部。弹窗、抽屉中的录入操作采用同一可见性原则，并与其容器的滚动方式匹配。

## 6. 标准 PC 表格列表

本节适用于以“范围 Tab（需要时）—筛选区—操作区—表格—分页”为主体的 PC 列表。客户、联系人、线索等标准表格列表采用这一交互形式。日报的三栏审阅、日程的周／月视图等已有独立结构的页面，不因本节改成普通表格；它们仍遵守第 2～4 节通用的信息呈现规则。

### 6.1 筛选区

1. 参考 PC 客户列表的筛选区样式，默认展示一行筛选项。筛选项较少且能在一行完整展示时，全部直接展示，不设置“更多筛选”；超出一行时，首行保留本页高频项，其余收在“更多筛选”中。不得为了制造“更多筛选”而拆分本可放在同一行的筛选项。统一布局，不要求各列表使用相同的筛选字段。
2. 查询、重置条件保持清晰可见；存在“更多筛选”时，展开／收起入口也保持清晰可见。筛选项即使收起，其已生效的条件仍参与结果计算；重新展开时保留当前选择。
3. 数据范围 Tab、业务状态和时间条件分别判断，不能把范围切换等同于状态或时间筛选。各列表的默认条件、返回恢复和菜单重新进入行为沿用当前 PRD 的规定，不在本文另设业务默认值。

### 6.2 范围 Tab

1. 有多个数据范围的列表，统一使用 PC 客户列表的 Tab 位置、外观与选中态；没有范围切换需求的列表不强制增加 Tab。
2. Tab 名称、顺序、纳入条件和角色可见性由对应模块规则决定，不照搬客户列表的“全部／团队／我负责的／我协作的”。“全部”始终仅指当前用户有权查看的全部记录。
3. 切换范围后，筛选、结果数和表格均按当前范围重新计算；同一列表不因切换范围另换一套展示字段，除非对应 PRD 明确要求。

### 6.3 表格与横向浏览

1. 参考 PC 客户列表的字段列方式，一个字段对应一列；不把几个独立字段拼在同一单元格中。多值字段可在所属单列中按业务规则展示。
2. 字段较多时仅在表格区域横向滚动，不挤压字段到难以辨认；列显示设置沿用各列表已确认的字段范围。是否提供左右浏览按钮可随表格宽度决定，但鼠标、触控板及键盘仍应能操作横向滚动区域。
3. 有行选择框时，将其列冻结在最左侧；有行操作按钮时，将操作列放在最右侧并冻结。缺少对应功能的列表不增加空列。选择框和操作列不是可隐藏的业务字段，不能通过列显示设置关闭。
4. 左右冻结列与表头在滚动时保持对齐，背景与层级不得遮挡中间字段；窄窗口下仍须留出可横向浏览的内容宽度。PC 客户列表目前只实现首列冻结，末尾操作列冻结属于本节新增要求，不能直接把其现状当作完成标准。

### 6.4 列表页面说明

页面说明按以下顺序组织，避免在正文和说明中重复铺陈：

1. **页面契约信息：**按第 4.1 节展示页面编号、适用端、依据、覆盖范围和验收项。
2. **页面介绍：**用简短文字说明列表管理的对象与用途。
3. **操作按钮说明：**在页面介绍之后用表格说明本页的业务功能操作，例如本模块页面入口、新建、导入、导出、进入详情及具体批量业务动作；同一用途的成对入口可合并一行。第一列统一写为“【位置】按钮名称”，如“【顶部】联系人列表／全国公海”，位置名称与页面实际区域一致，不使用“位置·按钮”写法。列明按钮作用与结果、可用条件或权限。通用的更多筛选、查询、重置、分页、横向浏览、列设置、勾选与清空、弹窗取消/关闭/确认，以及黄色规则标签不逐项列入；只有其业务后果具有本页特殊规则时，才在相关业务按钮、筛选项、字段或范围说明中交代。未提供的操作不列入。
4. **角色权限与数据范围：**先用角色表列出本页各正式角色的可查看数据范围、可见范围 Tab 和可用操作，再逐个说明范围 Tab 的纳入条件；无 Tab 时直接说明本页数据范围。角色表的操作列区分通用浏览操作与需单独授权的业务按钮，明确对象范围和状态约束，不把原型固定演示身份、可见按钮或角色名称当作正式授权。仅在角色确有差异时展开差异，不机械复制通用权限表。
5. **筛选项表：**逐项列出筛选项名称、控件与选项范围／来源、默认值、筛选作用或特殊联动；实际存在“更多筛选”时区分首行与更多筛选，单行展示时统一标为首行。
6. **列表字段表：**逐列列出字段名称、含义／来源、展示方式及是否默认显示；列显示设置中的可选字段也应纳入。选择框与操作列单独说明用途，不当作业务字段。

操作按钮说明、角色权限与数据范围、筛选项表、列表字段表分别采用以下表头；实际内容按当前页面与 PRD 填写，不照抄示例字段：

| 位置／按钮 | 作用与结果 | 可用条件／权限 |
| --- | --- | --- |
| 【实际位置】本页业务按钮 | 点击后的行为及结果 | 对象状态、选择条件和必要的按钮权限 |

| 角色 | 可查看数据范围／可见 Tab | 可用操作 |
| --- | --- | --- |
| 本页适用的正式角色 | 本角色有权记录及可见的范围入口 | 通用浏览操作；需单独授权的业务动作及对象约束 |

| 筛选项 | 位置与控件 | 选项范围／来源 | 默认值 | 作用与特殊规则 |
| --- | --- | --- | --- | --- |
| 本页筛选项名称 | 首行或更多筛选；输入框、下拉等 | 固定选项或业务数据来源 | 本页默认值 | 匹配范围及必要的联动说明 |

| 列表字段 | 含义／来源 | 展示方式 | 默认显示 |
| --- | --- | --- | --- |
| 与表头一致的字段名 | 对应对象字段或派生值 | 文本、状态、日期等 | 是／否 |

排序规则归“筛选项表”，不混入操作按钮或数据范围；字段表与筛选项表描述完整配置，不在每个控件旁重复放黄色标签。

### 6.5 列表黄色标签

黄色标签只解释某个具体控件或操作附近的特殊判断、操作后果及原型评审边界，例如批量选择的作用范围、特定行操作的触发条件、横向浏览方式或结果数的特殊排除项。完整的 Tab 纳入范围、全部筛选选项、全部表格字段与角色差异保留在页面说明中，不拆成一串字段标签。

同一事实不在黄色浮窗和页面说明中逐字重复：页面说明给出完整清单和整体口径；黄色标签仅补充在当前操作位置需要即时理解的局部规则。表格中的真实状态、结果数、错误及不可操作状态仍直接显示，不藏入标签。

## 7. 原型检查口径

逐页核对：无效常驻提示已清理；黄色标签就近、可打开和关闭且同一规则不重复；页面说明顶部的契约三列表格、覆盖范围和验收项与当前依据一致，底部无重复契约或占位文字；页面说明与实际字段一致；无实际差异的角色权限内容已省略；录入页字段表完整，滚动后主要操作仍可见且不遮挡字段。标准 PC 表格列表另核对默认一行筛选、范围 Tab、字段列、横向滚动、存在时的选择框与操作列冻结，以及页面说明中的操作按钮表、角色权限与数据范围表、筛选项表和字段表；按钮、角色与当前页面及 PRD 逐项对应。检查 PC 与 H5 时分别覆盖其实际布局。

本文未纳入额外的校验时机、未保存离开提醒、重复提交处理等新规范；这些事项待另行确认。
