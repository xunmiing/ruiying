- 已配置销售、销售主管／经理、管理员（运营）三类人工角色和独立 Agent／服务身份。
- 已准备两个区域、两条业务线、销售场景、流程模板、阶段任务、线索池、全国客户公海、任务来源／流程属性规则、固定日报模板和消息系统白名单。

- 已准备四类客户、待治理客户、单业务线和多业务线商机、重复客户、带异常事项客户、门店、联系人关系、当前地址和历史快照样本。
- 外部能力均可通过开关模拟正常、超时、失败和无权限；全部数据为脱敏或合成数据。

### 6.1 本期列表与技术记录验收数据

- 同一销售、主管账号分别准备本人、团队、协作记录和超出权限记录；五类 PC 列表从菜单进入均为“全部可见范围”，越权记录不返回。
- 任务准备待处理、已完成、已取消各一条和 AI 待确认候选一条；默认任务列表包含前三条，候选不进入。今日、本周、逾期、状态筛选分别选择后才生效。
- 日报准备当天已提交、当天草稿和历史日报；从菜单进入默认当天、状态不限；无今日日报时显示空态。
- 权限校验、同步重试、消息投递和业务审计记录由技术人员查看分析并处理；测试通过接口或技术记录核对结果，不依赖独立前台管理页。

## 7. 验收用例统一模板与判定

核心用例按需填写：

| 字段 | 要求 |
|---|---|
| 前置 | 三角色、功能列表/按钮权限及固定数据范围、对象状态、外部服务状态、必要测试数据 |
| 入口 | H5 或 PC、页面／视图 ID、进入路径 |
| 操作 | 输入、步骤、并发／重复提交方式 |
| 服务端校验 | 功能列表/按钮权限、角色数据范围、状态、唯一性、版本、资格、上限、保护期、幂等 |
| 正式事实 | 新增／修改的对象、关系、状态、快照和未发生变化的对象 |
| 页面结果 | 成功、部分失败、失败、无权、并发冲突和可执行下一步 |
| 历史与审计 | 操作历史、系统审计、批次及子任务结果 |
| 影响 | 对其他角色、权限、历史、下游和通知的影响 |

通过判定：页面结果、正式业务事实、权限结果和审计结果全部符合预期，且失败场景无重复、半迁移、静默覆盖、重复经营权或数据侧漏。

上线阻断：影响销售闭环、核心数据正确性、权限安全或用户中心／业务线关键协作的 P0 用例任一失败；实施参数未配置且既无安全默认值也未关闭能力。

三角色权限测试：

- 分别验证销售、销售主管/经理、管理员（运营）的固定数据范围，以及功能列表与按钮权限组合。
- 销售可查看本人负责、本人协作、有成员资格的池待认领线索完整信息和全国公海完整客户详情；主管/经理增加本团队，管理员查看全部。
- 有权查看记录即可查看全部业务字段；获得查看权不等于获得编辑、认领或导出按钮权限。
- 角色或团队成员关系变更后，列表、详情、深链、导出与 Agent 同步收敛；最后一名管理员不可撤销。
- Agent 服务身份不计入三个人工角色，用户主动调用时取用户权限与服务身份能力交集。

## 8. 回归与交付判断

- 关闭 Agent、企微日历、定位或任一销售活动渠道后，客户—线索—商机—销售活动—任务—日报主链仍可手工完成。
- H5 页面和 PC 配置使用相同状态、枚举、权限与对象 ID；不存在页面能操作而接口拒绝之外的隐藏第二套规则。
- 所有失败状态给出用户下一步和技术错误编号；重复提交、重试和并发认领不产生重复或半完成记录。
- 以上 P0 用例通过后方可进入两区域试点准备；试点人员、周期、数据范围和量化指标另行回填。
