# 07 权限、通知、审计与异常模块 PRD

> 本版权限变更：仅销售、销售主管/经理、管理员（运营）三个人工角色；配置功能列表与按钮权限；按固定角色范围查看完整业务信息。PC 与 H5 原型使用固定演示账号，H5 的正式角色与权限逻辑集中展示在页面说明中。

> 版本：V0.29｜日期：2026-10-09｜状态：已同步本期商机字段范围与 PC 权限口径
> 历史变更（V0.26）：R4 能力包由「高影响治理」改为「授权范围内直接编辑客户资料」；审计覆盖项由「客户治理」改为「客户资料修改」；门店不产生权限对象。
> 上位文档：../prd.md、assets/permission-model.md、08-PC基础平台与集成治理.md。

PC 系统管理仅保留一个“人员组织与权限”入口，内部承接组织人员、角色权限、待处理、移交及同步异常。正式权限校验、同步重试、消息投递及审计记录必须保留；相关审计记录由技术人员查看分析并处理，具体的规则由技术定义。前台不建设独立系统审计、投递记录和消息模板管理页面。

## 1. 模块目标

保证同一用户在首页、搜索、列表、详情、Agent、消息、普通业务导出和深链中使用同一权限与数据范围；高影响操作正式审计；自动处理失败后可进入统一异常事项并人工接管。

## 2. 角色与权限

0.1 只保留销售、销售主管/经理、管理员（运营）三个人工角色。销售可查看本人负责与协作记录、有成员资格的池内待认领线索完整信息及全国公海完整客户详情；主管/经理增加本团队业务记录；管理员（运营）可查看全部业务记录。

只配置功能列表权限和按钮权限。菜单、页面、列表由功能列表权限控制；详情、创建、编辑、认领、分派、合并、下钻、导出、发布、启停、重试等由按钮权限控制。后端按角色固定数据范围、对象状态与正式业务规则逐次校验。管理员（运营）拥有全部数据查看范围，操作仍需按钮权限；原客户数据管理能力并入相应按钮，不再设置独立能力包或固定最高权限角色。

有权查看一条业务记录，即可查看其全部业务字段；不配置字段范围、独立明文查看权限或按角色脱敏。全国公海与池内待认领对象的查看权不等于认领按钮权限。关联的另一条独立业务对象仍需按其自身数据范围鉴权。

系统至少保留一名有效管理员（运营）；管理员角色的授予和撤销由有权限的管理员执行，最后一名不可撤销。管理员也不能查看明文密码、Token 或密钥，不能修改不可篡改审计或外部事实源，不能绕过正式业务规则直接修改底层数据。

Agent/服务身份是非人工调用身份，不计入三角色。用户主动调用时取用户权限与服务身份能力交集；系统预生成使用明确的服务身份和目标用户范围。来源撤权后立即停止无权访问，候选失效；正式写入后按源业务模块权限访问。

### 2.1 跨入口一致性

- 首页快捷入口按功能列表权限过滤，业务深链直接进入目标并重新鉴权。
- 搜索、列表、详情、关联关系、分析下钻、消息深链、导出和下载使用同一角色数据范围。
- 无权数据不返回结果、数量、摘要、标题或隐藏关系数量。
- 对象合并旧链接跳转主记录；对主记录无权时不泄露内容。
- 门店不在 0.1 范围，不产生任何权限对象。
- 撤权不删除业务事实或自动移交责任；已下载到系统外的文件不能追回。

## 3. 人员变化

公司用户中心是组织、人员及销售准入资格事实源。合格人员自动获得销售角色；异常工号不创建正式人员。瑞赢只消费公司企微认证结果，不建设绑定、改绑或人工身份映射。

团队成员关系、人员角色或销售资格变化影响权限时，立即重算角色数据范围，生成权限待处理及受影响对象清单；不自动移交业务责任。

停用、离职或资格失效时先立即停用，再按对象当前责任生成待移交清单。不同对象可选择不同接收人，执行支持部分成功和失败重试，历史责任保留。

0.1 不建设临时代办。

## 4. 字段、原件与 Agent

| 数据 | 规则 |
|---|---|
| 联系方式 | 手机号、邮箱允许作为预定义核心字段搜索；是否可见仍按当前对象权限和数据范围 |

| Agent 来源 | 只使用当前用户有权的最小必要内容；权限撤销后不可继续查看原文 |
| 定位 | 单次业务用途，不采集连续轨迹，不作为考勤 |
| 原件 | 依附销售活动或正式拜访，按对象权限查看／下载；普通用户不能替换或删除正式证据；管理员（运营） 可处置 |
| 知识 | 只有已发布且当前用户在发布范围内的版本可搜索、下载或被 Agent 引用 |

Agent服务身份 写入必须记录调用用户、服务身份、来源和结果。

## 5. 消息与投递

### 5.1 消息事实

站内消息是正式消息记录，企业微信是额外提醒渠道。消息已读／未读与来源对象状态、投递状态完全独立。

业务事件发生时计算并保存接收人快照，后续人员变化不改写历史消息。

### 5.2 企业微信白名单

只有产品定义的重要事件白名单可以发送企微。白名单事件须标明“系统必达”或“个人可关闭”：新任务指派、新移交处理待办、拜访异常需销售补充为系统必达；任务临期／逾期和日报未提交提醒为个人可关闭，默认开启。个人在 H5 M27 修改可关闭类别的开关，只影响保存后产生的新企微投递；系统必达项只读。站内正式消息始终生成并按原规则留痕，个人开关不删除或屏蔽站内消息。0.1 不建设静默时段、消息合并窗口或通用渠道降级链。

### 5.3 投递失败

投递状态为“待发送／发送中／成功／失败”。失败先自动重试；超过上限创建“消息投递失败”异常事项，管理员（运营） 可人工重试。重试成功后异常事项完成。

投递失败不得回滚来源业务事务，站内消息与企微分别独立发送。

## 6. 统一异常事项

状态：

> 待处理 → 处理中 → 已完成 / 不采纳

- 待处理默认无处理人。
- 有权用户“领取处理”后成为处理人并进入处理中；并发领取只允许一人成功。
- 处理中可“退回待处理”，清空处理人。
- 有重指派按钮权限的管理员（运营）可重新指定处理人；处理人停用时自动退回待处理。
- 同一“对象 + 异常类型 + 目标字段／关系”同一时间只有一条未完成事项。
- 异常事项不能直接修改正式业务事实，必须跳转源对象使用正式动作。
- 0.1 不建设 SLA、自动升级、自动催办或复杂工单调度。

## 7. 正式审计

至少覆盖：

- 高影响业务操作和客户资料修改（含客户关系网、经营关系）；本期不产生客户合并与恢复动作；
- 角色及功能列表/按钮权限授予／撤销、团队范围变化；
- 配置发布；
- 批量、导入、导出；
- 同步、消息投递和重要系统治理动作。

06 配置和分析至少审计：A 类创建、修改、启停；B 类草稿、校验、发布、发布失败、停用、恢复；指标口径和版本；Agent 能力、来源、试点范围和预生成参数；导出发起、完成、失败和下载。普通打开页面、查询和筛选不做业务级操作审计。

以下操作强制填写原因：B 类发布／停用／恢复、指标发布／停用、Agent 扩大试点范围、Agent 关闭存在业务影响的能力、高影响 A 类停用，以及已产生业务影响配置的特殊恢复／纠错。普通 A 类字段编辑、名称、排序、草稿保存、查询筛选和 Agent 预生成时间普通调整不强制原因。

审计至少记录操作时间、操作人、来源（PC／H5／Agent服务身份／系统任务）、对象类型和标识、动作、结果、实际变化的关键前后值、失败原因及关联批量／导入／同步／异常事项记录。

不复制完整对象快照、大文本、文件正文或原件正文。

审计只增不改，业务侧不可删除；不跟随处理记录 7 天删除。有审计功能和按钮权限的管理员（运营）可查看全部审计；其他角色仅查看有权范围内获准的记录。

0.1 不做审计导出、审计报表、访问行为分析或技术调用链分析。

06 相关主动通知仅覆盖需要行动的结果：B 类或指标发布失败通知发布人，异步导出完成／失败通知发起人，重大系统异常交 08 统一治理。普通 A 类保存只留审计，不群发通知。

## 8. 批量、幂等与冲突

- 批量支持当前页、跨页及全部筛选结果，单次上限 100 条。
- 所有批量异步执行，执行前预检，正式执行时逐条重检。
- 单条失败不影响其他记录；成功项不重复，失败项可按原参数重试。
- 重试重新校验权限、状态、版本和业务规则。
- 高影响写操作使用请求唯一标识和幂等机制。
- 网络超时区分成功、失败、处理中和结果确认中。
- 版本冲突留在当前页面，提示刷新后重新操作，不静默覆盖。

处理记录只展示本人发起的批量、导入和导出，保留 7 天；它不是正式审计。

## 9. 外部依赖与安全降级

| 依赖 | 失败时规则 |
|---|---|
| 权限／身份服务 | 可短时使用有有效期的最近有效缓存；无有效缓存则拒绝访问，不默认放大权限 |
| Agent | 核心流程可手工完成 |
| 通知渠道 | 业务继续，记录失败并重试 |
| 地图／定位 | 允许说明原因并继续记录，不伪造定位 |
| 企微日程 | 瑞赢源对象继续成立，失败进入同步任务；API 不支持双向时降级单向 |
| 原件渠道 | 保存有权元数据或手工业务内容，不生成无权原文 |
| 知识 | 只使用当前可访问的正式版本，不复制越权内容 |
| 业务线系统 | 历史快照可读，新建不能选择未知或失效值 |

外部系统不是当前正式事实源时，其失败不得阻断瑞赢内部可完成的核心业务。

## 10. 验收

1. 同一用户在 H5、PC、搜索、详情、消息深链、分析下钻、Agent 和导出中使用同一权限与数据范围。
2. 无权用户不能通过 URL、接口、数量、摘要、隐藏关系或 Agent 来源获得数据。
3. 管理员（运营）可查看全部业务数据，操作按功能列表/按钮及业务规则校验；最后一名管理员不可撤销。
4. 管理员（运营）不能查看明文系统凭证、修改审计或外部事实，也不能绕过业务规则。
5. 仅三个人工角色；Agent 服务身份取调用用户权限与服务身份能力交集。
6. 调岗立即停旧范围但不自动授予新范围；停用先禁用再移交。
7. 0.1 不存在临时代办对象、页面、授权或消息。
8. 原件按业务对象权限处理，普通用户不可替换／删除，管理员（运营） 可处置。
9. 并发领取同一异常事项只有一人成功；重复异常不重复建单。
10. 消息投递失败不回滚业务，超限创建统一异常事项。
11. 权限、配置、批量、导入、导出和 Agent服务身份 写入均可在正式审计追溯。
12. 审计不可修改／删除，不提供导出，且不按 7 天清理。
13. 权限服务异常时只用有效缓存，否则拒绝。
14. 高影响写入超时不重复产生业务事实。
