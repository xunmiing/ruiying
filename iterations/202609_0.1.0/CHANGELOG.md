## 1. 这个文件是什么

**0.1 迭代的更新记录总账。** 每次 0.1 的更新都在这里追加一条，用来回答三个问题：

- 这次改了什么、影响哪些文件；
- 依据哪条确认结论（`DEC-xxx` 或本次范围确认）；
- 验收到什么程度、还欠什么。

### 与其他文件的分工

| 文件 | 记录什么 |
|---|---|
| **本文件** | 0.1 每次更新的**时间线、改动文件、验证程度、遗留项** |
| `瑞赢首个销售闭环/prd.md` §版本历史 | 主 PRD 的正式修订说明（业务规则变更的唯一出处） |
| `瑞赢首个销售闭环/prd/0X-*.md` | 各模块**当前生效**的规则事实 |
| `瑞赢首个销售闭环/prototype/CHANGELOG.md` | 原型**页面级**改动（文件、页面、交互、回归结果） |
| `research/2026Q3-ruiying-0to1-design_瑞赢0到1设计/decision-register.md` | 已确认决策的正式登记 |

**本文件只做时间线索引，不重新定义规则。** 业务规则冲突时以 PRD 与决策登记簿为准。

## 2. 记录约定

1. 每次更新追加一条，**最新的在最上面**（倒序）。
2. 每条至少写：日期、主题、依据、改动文件、验证程度、遗留项。
3. **不修改历史条目。** 后续推翻先前结论时，在新条目里写明「取代／调整」关系。
4. 只改 PRD 或只改原型的更新也要记一条，并明确写出「另一侧未同步」。
5. 版本号引用 `prd.md` 的版本历史；主 PRD 存在跳号（V0.7／V0.17／V0.20／V0.25／V0.27 未登记），本文件按实际发生的更新记录，不回填跳号。
