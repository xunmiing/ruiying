## 0. 本次变更（DEC-061）

**本次新增／调整**

- 销售手工新增、线索转换新建、集团候选正式确认和批量导入，必须将客户主档与一条初始经营关系作为同一事务创建。
- 初始经营关系必须有且仅有一个区域、一个业务线、一个主负责人。负责人默认创建人且可修改，不按创建人角色改写，0.1 不做经营资格阻断。
- 负责人只有一个关联区域时自动带出，有多个时必须选择；修改负责人后刷新可选区域。选择关联范围外的有效区域只提示、不阻断。
- 业务方向未明时可选「未明确业务线」。它只是关系占位，不匹配商机模板、不计正式业务线业绩；同客户＋区域最多一条有效占位关系。
- 区域、业务线或负责人失败时整体回滚，不产生孤立客户或孤立经营关系；重复提交按幂等键返回同一结果。
- 所有角色的客户列表均增加「全部客户」；它只包含至少一条有效经营关系的客户，不包含全国公海客户。「我负责的」与「我协作的」仍主负责优先且互斥；有团队管理权限时增加「团队客户」。
- 全国公海改为客户主档公海：只收纳零条有效经营关系的客户。停止最后一条有效关系时自动入池；认领／分派时原子结束公海记录并新建初始经营关系。
- 客户列表及其筛选只读取有效经营关系；公海客户和已停止关系不得显示为「全国公海待分配」经营关系。
- 全国公海列表以客户主档为一行，不展示「经营单位」、当前经营区域或当前业务线；认领／分派时再指定初始关系。
- 原“组织关系”统一更名为“客户关系网”，支持集团关系、总分关系、上游、下游四类关系；每条只维护关联客户、关系类型、关系标签和备注。
- 客户资料治理退出 0.1。资料修改采用权限控制：有编辑权限直接修改并立即生效，无权限只读并联系有权限的主管或销售运营；所有修改在历史中记录修改时间、修改人、字段、修改前和修改后内容。
- 门店退出 0.1：删除菜单／入口、原型页面、前端页面、业务逻辑和专属交互；仅作为后续版本候选保留说明。
- 经营关系不再提供「释放至全国公海」动作。只保留「停止经营」；停止后若客户仍有其他有效关系则不入池，若已无有效关系则系统自动入池。

**本次不做**

- 不建设客户级负责人或「我新建待处理」Tab。
- 不在本次新增联系人与联系人之间的关系模型。
- 不建设客户资料修改申请、治理事项、审批或复核流程。

PC 从菜单进入客户列表时，范围顺序固定为“全部／团队／我负责的／我协作的”，默认全部可见客户，状态与时间均不限制。同一范围内按客户 ID 去重；从详情返回恢复 Tab、筛选、排序和页码，从菜单再次进入重置为默认值。客户关系网及有效经营关系仍按本模块规则维护。

## 1. 目标与边界

建立四类客户主体、联系人及其业务关系的统一事实，使销售、主管能在 H5／PC 完成客户经营闭环。

- 客户主档回答“主体是谁”；客户＋区域＋业务线经营关系回答“谁负责经营”。
- 主体、业务角色、销售经营资格分开；客户资料质量不阻断正常销售。
- 当前资料保存当前值；历史由关系有效期、操作审计和业务快照保留。
- 不建设公共占位客户、复杂客户组织树、全局地址主档或联系人之间关系。

## 2. 对象关系

```text
客户（集团／组织／个体工商户／自然人）
├─ 0..N 客户地址
├─ 0..N 联系人关系 ── N..1 联系人
├─ 0..N 客户关系网（关联客户＋类型＋标签＋备注）
├─ 0..N 客户＋区域＋业务线经营关系
│  ├─ 0..1 主负责人
│  ├─ 0..N 协作人
│  └─ 0..1 当前全国公海占用记录
└─ 0..N 修改历史
```

## 3. 客户主体

### 3.1 类型、名称与创建

| 类型 | 0.1 口径 |
|---|---|
| 集团客户 | 销售提交集团候选，管理员（运营） 查重确认后创建；正式创建前围绕实际经营实体推进。 |
| 组织客户 | 有独立组织／登记身份，名称优先用当前正式完整名称。 |
| 个体工商户 | 填写登记名称，不以经营者姓名替代。 |
| 自然人客户 | 仅个人身份交易或经营时创建；仅作为联系人不自动建自然人客户。 |

名称仅保留“客户名称”和“其他名称”。其他名称保存简称、品牌名、曾用名或常用称呼，参与搜索和疑似重复识别，不替代主名称或单独证明主体相同。0.1 不拆法定名称、展示名称、名称类型、来源、版本或独立名称表。

### 3.2 查重与工商

- 组织、个体工商户允许暂缺统一社会信用代码，不阻断销售。
- 信用代码规范化后全库精确相同必须阻断；无权候选只提示冲突，不泄露详情。
- 客户名称相同／高度相似时强提示；用户说明原因后可继续。其他名称仅作辅助，系统不自动合并。
- 工商查询成功后展示来源与时间，用户确认后可带入表单；不得静默覆盖主档。
- 未找到、失败、超时或不可用不阻断手工创建和经营，不清空最后成功快照。
- 工商刷新只更新外部快照；差异只提示，不静默覆盖客户资料。

### 3.3 客户记录状态

本期客户记录均为正常记录；不设置“已合并”状态，不预置历史合并数据。

0.1 不设置独立的客户身份核验状态，不提供身份核验按钮。工商查询结果、信用代码查重、资料质量标签和客户记录状态分别按各自规则处理；不得将工商查询成功或资料完整推断为“身份已核验”。

### 3.4 编辑权限与修改历史

客户资料采用“权限控制＋修改历史”。有对应编辑权限者直接修改并立即生效；无编辑权限者只能查看，需要修改时联系有权限的主管或销售运营线下处理。不提供资料修改申请、治理事项、资料审批或资料复核流程。每次修改至少记录修改时间、修改人、修改字段、修改前内容和修改后内容。

客户名称、客户类型、统一社会信用代码、工商注册地址由主体资料编辑按钮权限控制；其他客户资料按普通字段或地址编辑按钮权限维护。编辑后直接生效并记录前后值。客户详情不在这些字段旁展示“高影响”标记或对应的黄色说明标签；字段是否填写、价值分级均不改变编辑权限。资料编辑不自动触发审批或复核。

0.1 不提供合并客户或恢复客户操作，不配置对应按钮权限，也不因疑似重复自动合并；本期系统没有客户合并逻辑或历史合并数据。

## 4. 客户关系网

客户关系网用于表达当前客户与其他客户之间的业务或组织关联。0.1 支持四类关系：

| 关系类型 | 建议关系标签 |
|---|---|
| 集团关系 | 集团总部、成员企业、母公司、子公司 |
| 总分关系 | 总公司、分公司、总部、分支机构 |
| 上游 | 供应商、服务商、品牌商、制造商 |
| 下游 | 经销商、代理商、渠道商、终端客户 |

每条关系只维护关联客户、关系类型、关系标签和备注。关系标签用于快速识别；合作模式、股权或控制情况、实际业务关系、品牌关系、特殊背景及其他补充统一写入备注，不增加结构化字段。

0.1 不建设股权比例、控股比例、实际控制人关系、有效期、关系权重、多层股权穿透、自定义关系类型或复杂关系审批／治理。关系不产生经营资格，也不扩大数据权限。

## 5. 联系人

- 联系人独立存在，经关系多对多关联客户。销售人工创建正式联系人时必须同时关联至少一个真实客户，不开放孤立创建。
- 一个联系人可登记多个手机号、多个微信号；各自按顺序指定首条为主要联系方式。手机号规范化精确命中任一已有号码时强提示复用，但可说明后继续创建，不设绝对唯一或自动合并。
- 同一联系人＋客户同一时间一条有效关系；角色多选；主要联系人允许多个。所属单位、部门、职务、角色、主要联系人、有效期存于关系。
- 姓名、全部手机号与微信号、邮箱、联系地址为共享基础资料。用户须同时具备至少一条可见客户关系普通编辑权限和联系人基础资料编辑权限方可修改；即时影响所有关系，页面提示、乐观锁并留痕。列表可展示主要手机号及总数，详情可逐条查看和维护。
- 普通销售的联系人列表、搜索和独立详情，以本人主负责或协作客户的关系为查看依据；主管/经理增加本团队客户，管理员（运营）查看全部。联系人创建人不单独取得持续查看权；失去最后一条上述可见客户关系后，联系人从普通列表消失，独立详情深链也不可进入。历史业务仍按自身权限展示。
- 联系人关联多家客户时，普通列表和独立详情只显示当前用户上述范围内的客户关系，不显示无权客户名称、详情或隐藏数量；共享基础资料在有查看权时完整展示。全国公海客户认领前的联系人供销售及主管/经理从该公海客户详情查看完整信息，不因公海客户可见而进入其普通联系人列表、搜索或独立详情；查看不赋予编辑、关系维护权限。管理员（运营）仍按全部数据范围查看联系人。
- 有权查看联系人记录即可在列表、搜索、查重候选和详情查看完整手机号、微信、邮箱并单条复制；一期不做字段范围或明文查看权限。导出按按钮权限并逐条校验对象数据范围。
- 0.1 审计联系方式修改、导出和权限配置，不逐次审计普通查看／单条复制。

## 6. 门店

门店能力不进入 0.1。菜单入口、原型页面、前端页面、相关业务逻辑、页面交互及仅服务于门店的前端代码均删除，不以大段注释保留。后续如重新进入版本范围，作为候选能力另行确认并从现有备份恢复。

## 7. 地址

0.1 只维护当前值，不建全局主档、复用、版本、默认地址、停用／失效状态、历史列表或恢复。

- 客户地址类型：注册地址、办公地址、经营地址、项目／服务地址。注册地址由 管理员（运营） 处理；其他地址由普通编辑者新增、修改或移除。
- 移除后不再作为当前地址或新业务候选；审计完整值、类型、操作人、时间和选填说明；重新使用时重新新增。
- 联系人维护一个选填“联系地址”，不区分工作、邮寄、私人或默认采集家庭地址。
- 业务对象保存发生时地址文本快照，不随当前值变化。
- 已打开表单引用的地址被移除时，提交必须强制提示并要求确认，不得静默切换；确认原地址仍为实际地点后可按文本保存。

## 8. 客户价值与经营关系

### 8.1 客户价值

四类客户均可维护公司级“战略／重点／普通／机会”；空值显示“未分级”，不阻断业务。集团与成员各自维护，不继承。

- 有客户价值编辑按钮权限且客户在数据范围内的人员可直接设置或调整，保存后立即生效；主管如需修正，使用同一编辑动作。
- 首次设置说明选填，再次调整说明必填；每次变更在日志记录前后值、操作人、时间和说明。
- 不设待复核／已复核状态、主管复核按钮、7 天期限或超期提醒；不建审批流、系统／AI 建议、评分、周期复核、下次复核日期或批量修改。

### 8.2 经营关系

最小单元是客户＋区域＋业务线，状态仅“有效／停止经营”；删除高／中／低／暂不经营等经营优先级。

- 客户主档不保存负责人。销售手工新增、线索转换新建、集团候选正式确认和批量导入都必须同时创建一条初始经营关系。
- 初始关系必须有且仅有一个区域、一个业务线和一个主负责人。负责人默认创建人、可修改，不按角色改写；0.1 不做经营资格阻断。
- 负责人唯一关联区域自动带出，多区域必须选择；修改负责人后刷新。选择关联范围外的有效区域只提示、不阻断。
- 区域、业务线、负责人任一项失败时整体回滚，重复提交使用幂等键防止产生两个客户或两条初始关系。
- 「未明确业务线」是经营关系占位，不是正式业务线；不匹配商机模板、不计正式业务线业绩。同客户＋区域最多一条有效占位关系，明确后停止占位并新建具体关系。
- 同一有效单元一个主负责人、多个协作人。主负责人和主管可调整合资格协作人；协作人可参与普通销售业务但不能管理经营权。
- 主管可直接转派主负责人，不经公海；目标须通过资格和上限校验，默认保留协作人，也可同次调整。
- 停止经营结束当前负责人及协作人并保留历史；若这是客户最后一条有效关系，客户自动进入全国公海。

## 9. 客户公海

全国公海流转零条有效经营关系的客户主档，不是经营单元池。

- 0.1 只建设一个全国公海。客户停止最后一条有效经营关系时自动入池，不设可选勾选；仍有其他有效关系时不入池。
- 同一客户同时最多一条有效公海记录，且不得与有效经营关系并存。历史关系保留停止状态。
- 销售认领时主负责人固定为当前认领人；主管分派时选择主负责人。两者都必须选择区域和业务线，可选「未明确业务线」。
- 认领／分派是同一原子动作：结束有效公海记录并新建有效经营关系。任一项失败时保持原公海状态；并发认领仅首人成功。
- 公海列表可展示客户名称、类型、价值、最近活动、入池时间和原因；所有销售可打开完整客户详情。原经营区域／原业务线仅是历史事实，不作为当前待领取单元。
- 保护期只由公海认领或公海分派产生；主动建关系和直接转派不产生。保护期内不参加普通批量回收，主管可填原因提前结束。
- 持有量按本人主负责的有效经营关系数计算；协作、停止、入池、历史不计。主动建关系、认领、分派、转派均校验；按销售或角色轻量配置，未配置不限，主管默认不能突破。
- 公海列表展示客户名称、类型、价值、最近活动日期、入池时间／原因、是否可认领和上限提示；所有销售可进入完整客户详情。详情中的独立关联对象仍按其自身数据范围鉴权；历史经营关系作为客户详情信息展示，不作为当前待领取单元。
- 0.1 不提供主动释放或主管回收入口；最后一条有效经营关系停止后系统自动将客户主档入池。

## 10. 客户资料修改历史

客户资料不建设独立治理流程。历史承担追溯，权限承担控制。修改日志至少记录修改时间、修改人、修改字段、修改前内容和修改后内容；日志只追加、不可由普通用户删除或修改。

| 地址 | 所属对象详情内维护，不设地址中心 | 同左，可查看类型筛选和修改历史 |
| 客户关系网 | 查看有权关系 | 查看并按权限维护关联客户、类型、标签和备注 |
| 公海／价值 | 所有销售查看公海完整客户详情；获授权销售认领／初判；主管分派／转派／复核 | 全部单条能力＋复杂筛选、批量分派、全国公海规则配置、历史、审计 |

页面、搜索、接口、直接 URL、关系图、数量和错误提示均不得侧漏无权数据。

## 12. 角色与权限

- 销售可查看本人主负责及作为协作人参与的客户经营关系；主负责人可按按钮权限管理本经营单元和协作人，协作人不因此获得经营权转移或停止按钮。
- 销售主管/经理增加本团队成员的客户经营关系，可按按钮权限分派、转派、回收、调整团队及复核价值。
- 管理员（运营）可查看全部客户资料及业务明细；配置公海规则、修改客户资料、合并、恢复、同步和异常处理均按相应功能列表及按钮权限操作。
- 全国公海客户对所有销售开放完整客户详情；认领/分派仍分别校验按钮权限、资格、上限、状态及并发。

0.1 仅配置功能列表和按钮权限，不设字段范围或独立明文权限。关联的独立业务记录仍按其自身数据范围鉴权；不建设通用单记录分享。系统至少保留一名有效管理员（运营），角色及权限变化进入正式审计。

## 13. 批量、并发与幂等

仅 PC 开放批量白名单：公海分派、停止经营、调整协作人、直接转派及独立授权后的导出。不提供批量「释放至全国公海」。

不批量：客户主体字段、客户价值、客户关系网、联系人基础资料。

- 逐条校验并允许部分成功；展示失败原因，只重试失败项。
- 批次 ID＋子任务幂等键，重复提交返回首次结果。
- 共享资料使用乐观锁；经营权动作使用服务端原子条件更新。
- 大批量可转异步，阈值由技术回填；完成、部分失败或失败时通知发起人。

## 14. 外部来源与降级

- 用户中心是人员、组织、岗位、区域、业务线资格、在离职状态事实源。短暂不可用用最后成功数据；未同步新用户不得替代创建；恢复后最新结果立即生效。最大兜底时限由安全技术回填。
- 业务线系统是事实源。同步失败保留最后成功值；停用后历史显示、新业务不可选，不自动停止或迁移已有数据；重新启用沿用稳定 ID。
- 工商是外部查询服务，不称主数据同步。保存来源、外部 ID、查询时间、来源更新时间、状态、快照／原始引用、最后成功时间和失败原因。
- 外部状态区分未查询／未同步、确实不存在、失败、较旧、正常成功；失败不清空最后成功结果。
- 0.1 完全不建设下游客户映射。

## 15. 审计与通知

业务对象历史与系统审计分视图、共用底层事实。客户字段修改、身份、客户关系网、合并恢复、经营权、公海、责任人、权限、自授权、导出和批量必须审计；普通用户不可删改。保存期限由安全／法务／技术回填，未确定前不得短期自动删除。

通知只覆盖需要他人知晓、后续行动或异步结果：主管转派、停止经营、协作人增删；最后一条有效关系停止后自动入池；公海分派；异步批量结果；明显权限变化；持续集成异常。客户价值直接设置或调整后由页面反馈并写日志，不发送待复核或超期通知。本人主动认领和已获页面反馈的普通操作不重复通知。优先企微应用消息，投递失败不回滚业务。

## 16. 验收重点

- 客户主档和初始经营关系一并成立；任一必需信息失败时均不出现孤立客户或关系，重复提交只产生一份业务结果。
- 三角色按固定数据范围查看有权客户及完整详情；销售可在全国公海查看完整客户详情，认领仍单独校验动作权限和经营资格。
- 客户查重、客户关系网、联系人、地址、价值和公海操作均正确保留业务历史；客户详情无合并入口，疑似重复不自动合并；无权操作给出明确提示。
- H5／PC 对同一客户展示一致的正式信息；批量部分失败、外部能力不可用和通知失败时，用户能识别已成功与未成功的业务结果。

## 17. 0.1 明确不做

公共占位客户；完整名称 MDM；门店；独立客户身份核验状态与操作；客户合并与恢复操作；客户资料治理流程；结构化股权／控制字段与穿透；自定义客户关系类型；复杂客户关系审批；全局地址／默认／版本／恢复／联系人多类型地址；经营优先级；价值复核、评分／AI 建议、周期复核与批量修改；主负责人主动释放全国公海；自动公海回收和 N 天预警；复杂异常工单、SLA、自动派单升级；通用单记录分享。
