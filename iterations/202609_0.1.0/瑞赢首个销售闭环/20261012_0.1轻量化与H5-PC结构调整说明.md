# 瑞赢 0.1 轻量化与 H5／PC 结构调整说明

> 日期：2026-10-12  
> 用途：汇总本轮关于两端定位、列表范围、管理分析退出及系统管理精简的讨论结论，供评审及后续回写使用。  
> 状态：本轮已确认口径汇总；具体待定项见第七节。本次仅新增本说明，尚未同步修改正式 PRD、原型及验收用例。  
> 依据：本轮用户逐项确认及最新修正；现有 PRD 用于定位影响范围。本文是本轮调整快照，正式回写后以更新后的 PRD 为设计事实源，不另行维护第二套 PRD。

## 一、调整目标

0.1 优先保证销售日常执行与主管团队业务处理闭环，控制分析平台和技术管理页面的建设量。

1. H5 优先方便销售个人使用，主管／经理只保留简单、高频的团队处理能力。
2. PC 优先方便主管／经理处理团队业务，同时支持主管承担个人销售任务、参与重点客户经营。
3. 销售与主管均可使用 PC、H5，两端重点不同，业务对象、状态和权限规则保持一致。
4. 列表采用固定的数据范围入口，不根据角色切换不同的默认 Tab；角色决定实际可见数据。
5. 管理分析整体移出 0.1；需要业务人员操作的管理功能保留页面，技术排障能力由技术实现和维护。

## 二、业务逻辑与范围调整

### 调整 01：明确 H5 与 PC 的使用重点

| 项目 | 调整后规则 | 调整原因 |
|---|---|---|
| H5 | 以销售个人执行为主，围绕工作台、任务、日程、互动、知识库组织日常操作 | 移动场景优先完成签到、记录、任务处理和日报等高频操作 |
| H5 主管能力 | 本期提供轻量团队处理；完整主管管理页面后续迭代 | 避免本期同时建设两套完整管理界面 |
| PC | 优先方便主管／经理查看团队业务、分派及跟进，同时保留个人销售操作 | 主管既管理团队，也直接经营客户和承担任务 |
| 端与角色 | 销售、主管均可使用两端；具体操作仍按正式权限执行 | 使用设备不应形成另一套角色或权限模型 |

H5 本期轻量团队处理范围：

| 业务 | 保留能力 |
|---|---|
| 团队任务 | 查看、单条派单、催办 |
| 团队日报 | 阅读、追加建议 |
| 团队线索 | 查看，按权限进行单条分派或转交 |
| 团队拜访 | 查看拜访及证据、单条复核 |

以上动作进入各源业务页面执行。正式任务不增加验收、退回或申请延期流程；日报不增加退回、重提。

### 调整 02：PC 首页保持轻量入口页

PC 首页继续承担导航入口作用，保留客户、线索、商机、任务、销售活动／拜访、日报等源业务入口，不扩展为指标看板或复杂管理工作台。

主管经常参与重点客户经营，客户相关入口继续保留。固定入口按功能权限开放；不按角色设计不同的首页默认 Tab。

**调整原因：** 主管可以快速进入业务处理，同时控制首页的开发和维护成本。销售活动与拜访入口沿用当前正式整合方案，本轮不另建重复入口。

### 调整 03：PC 列表统一默认数据范围为“全部”

适用模块：客户、任务、日报、线索、商机。

1. 从菜单进入时，数据范围默认“全部”。
2. “全部”指当前用户有权查看的全部记录，不等于全公司数据。
3. 主管的全部范围包含其有权查看的团队记录，以及本人负责、协作等其他已获授权记录；不能简单将“全部”等同于“团队”。
4. 有团队范围入口的列表，在“全部”之后优先排列“团队”，再排列个人或协作范围；不根据不同角色更换默认 Tab。
5. 同一模块切换数据范围时使用同一套展示字段，不为不同 Tab 单独设计字段布局。
6. 不强行为没有对应业务关系的模块增加“协作”Tab，例如日报不因此增加协作日报模型。

**调整原因：** 主管进入即可看到其有权业务全貌，同时能切换个人或协作范围；固定结构降低学习和实现成本。

本条源于本轮 PC 结构讨论。H5 仍以销售个人执行为重点，本轮不自动将其既有任务主 Tab、日程视图等全部改成 PC 的范围结构。

### 调整 04：客户列表明确四个范围

客户列表固定顺序：**全部｜团队｜我负责的｜我协作的**。

| 范围 | 含义 |
|---|---|
| 全部 | 当前用户有权查看的全部客户 |
| 团队 | 当前用户有权查看的团队客户 |
| 我负责的 | 当前用户在有效经营关系中担任负责人的客户 |
| 我协作的 | 当前用户在有效经营关系中作为协作人员参与的客户 |

按现有客户经营关系模型计算范围；同一列表内按客户去重。一个客户有多条经营关系时，可以同时符合多个范围，不要求各 Tab 互斥。

**调整原因：** 主管既看团队也经营个人重点客户，销售需要快速区分负责与协作客户。

现有页面清单中的客户列表“不设我的／团队 Tab”等冲突表述需要在正式回写时替换。客户关系网和经营关系继续保留。

### 调整 05：管理分析整体移出 0.1

| 移出内容 | 同步处理范围 |
|---|---|
| 管理分析看板 | 导航、页面、指标卡片、专题分析入口 |
| 指标趋势与指标下钻 | 趋势展示、下钻明细、指标条件跳转 |
| 管理分析专属导出 | 下钻导出入口、专属模板及相关要求 |
| 指标定义、指标版本 | 服务管理分析的指标配置页面及发布维护要求 |
| 相关配套要求 | 页面清单、权限项、验收条目及本期交付清单中的分析专项要求 |

移出的是本期交付范围，不删除普通业务列表所需的数量展示、筛选、普通导出和详情日志。

以下内容继续保留：

- 客户关系网：客户之间的关联关系。
- 经营关系：负责人、协作人员等基础经营资料。
- 商机阶段和停滞提醒、任务逾期标记等源业务规则。
- 主管在任务、日报、线索、商机、拜访等源业务页面的处理能力。

**调整原因：** 本期主管通过业务列表和详情完成管理工作，先减少独立分析页面、指标版本及下钻导出的建设量。

## 三、字段、状态与列表交互调整

### 调整 06：数据范围、状态、时间分别设置

| 模块 | 从菜单进入的默认数据范围 | 默认状态 | 默认时间 |
|---|---|---|---|
| 客户 | 全部可见范围 | 不限制 | 不限制 |
| 线索 | 全部可见范围 | 不限制 | 不限制 |
| 商机 | 全部可见范围 | 不限制 | 不限制 |
| 任务 | 全部可见范围 | 不限制 | 不限制 |
| 日报 | 全部可见范围 | 不限制 | 当天 |

1. 客户、线索、商机不预选状态和时间条件；用户需要时自行筛选。
2. 任务列表默认展示全部可见正式任务，不预选状态或时间；AI 候选仍归入“待确认”，两者不混用状态。
3. 日报时间以日报对应的业务日期为筛选语义；当天范围遵循系统统一业务日期口径。
4. “全部”只决定数据范围，不清除或代替独立的状态、时间条件。
5. 不因本轮列表调整修改正式任务仅“待处理、已完成、已取消”的既有状态模型。

**调整原因：** 避免一个 Tab 同时隐含人员归属、状态和日期，造成用户无法判断列表为什么缺少某条数据。

### 调整 07：菜单进入与详情返回采用不同规则

| 场景 | 规则 | 确认情况 |
|---|---|---|
| 从菜单进入列表 | 数据范围默认全部，状态和时间采用模块默认值 | 已确认 |
| 从列表进入详情后返回 | 恢复刚才的 Tab、筛选、排序和页码 | 已确认 |
| 从明确指向团队或特定条件的业务入口进入 | 保留入口携带的范围和条件 | 落地建议 |
| 直接打开详情，没有来源列表上下文 | 返回对应列表默认视图 | 落地建议 |

上述恢复是当前页面会话的返回行为，不增加个人保存视图或长期个性化默认设置。

**调整原因：** 菜单入口保持一致，连续查看和处理业务时保留工作位置。

## 四、系统管理页面精简

### 调整 08：人员、组织架构、角色与权限合并一个入口

统一入口名称：**人员组织与权限**。

该入口承接组织架构、人员及同步状态查看，角色和权限维护，以及停用、移交相关操作或记录。合并入口不要求将全部功能挤在同一张表中，可使用页面内分区或子页。

人员和组织基础信息仍以公司用户中心为来源；角色与权限维护继续遵循已确认的三角色、功能列表和按钮权限模型。

**调整原因：** 人员、组织和权限是同一管理链路，集中入口方便管理员处理，避免重复页面。

### 调整 09：保留业务人员需要操作的管理页面

| 页面 | 本期页面责任 |
|---|---|
| 人员组织与权限 | 组织及人员查看、角色与权限维护、停用及移交相关处理 |
| 业务配置 | 维护本期业务运行规则，子菜单见调整 11 |
| 异常事项 | 展示需要人工处理的业务异常、关联源对象、处理进展和结果 |
| 知识管理 | 知识新建、编辑、附件维护、发布范围、发布及停用 |
| AI 运行记录与失败处理 | 查看业务执行摘要、状态、失败原因及适用的重试结果 |

系统配置和治理操作权限归管理员；主管日常团队业务继续在源业务页面办理。AI 重试不得绕过人工确认或正式对象校验。

**调整原因：** 管理员需要可操作的业务入口；完整技术排障数据由技术查看和处理。

### 调整 10：技术能力保留，部分独立产品页面不建设

| 功能 | 0.1 页面调整 | 继续实现的能力 |
|---|---|---|
| 数据质量 | 不建设独立数据质量中心及规则管理页面 | 必要的业务校验、查重、缺失提示；符合既有异常事项范围的问题进入处理链路 |
| 集成与同步 | 不建设独立集成管理、同步任务排障页面 | 正式接口、同步执行、失败记录及重试 |
| 消息投递记录 | 不建设独立管理查询页面 | 消息投递结果、失败原因及重试日志 |
| 消息模板 | 不建设模板编辑管理页面 | 本期所需模板由技术配置和维护 |
| 系统审计 | 不建设独立系统审计列表、详情查询页面 | 必要审计记录及技术查看、分析、处理能力 |

保留边界：

- 消息中心、已读／未读和个人通知开关继续保留；个人通知开关与技术投递日志分别处理。
- 业务详情中的“日志记录”继续保留，不随系统审计查询页移出。
- 异常事项继续保留，不因数据质量中心移出而取消。
- 不因此重新引入客户资料修改审批或独立客户资料治理流程。
- AI 运行记录保留业务侧页面，完整技术日志由技术定义查看方式。

**调整原因：** 减少专门服务技术排障的产品页面，同时保证运行所需的权限、记录、恢复和人工处理能力。

### 调整 11：业务配置保留明确子菜单

按现有业务配置范围展开为以下结构：

```text
系统管理
├─ 人员组织与权限
├─ 业务配置
│  ├─ 字典管理
│  ├─ 商机流程模板
│  ├─ 线索池配置
│  ├─ 全国公海规则
│  ├─ 区域与业务线
│  ├─ 任务规则
│  ├─ 拜访规则
│  └─ Agent 配置
├─ 异常事项
├─ 知识管理
└─ AI 运行记录与失败处理
```

| 子菜单 | 主要内容 |
|---|---|
| 字典管理 | 业务选项、名称、排序和启停 |
| 商机流程模板 | 阶段、推进门槛、阶段任务和停滞规则 |
| 线索池配置 | 成员范围、认领、持有、保护和回收规则 |
| 全国公海规则 | 客户认领资格、持有上限、保护和回收规则 |
| 区域与业务线 | 经营区域、业务线及外部编码映射 |
| 任务规则 | 任务生成、截止和提醒规则；去掉已取消的验收相关配置 |
| 拜访规则 | 适用范围、签到凭证及异常判断规则 |
| Agent 配置 | 能力、来源、试点范围、预生成四个页面内页签 |

本轮保留配置能力，不重新扩大规则编辑范围；现有保存、校验、发布和版本绑定规则按正式模块执行。指标定义、指标版本退出本期；不增加消息模板子菜单。

**调整原因：** 业务配置覆盖不同业务对象，需要按实际任务拆分入口；不能只留下一个内容不明确的“业务配置”页面。

## 五、整体规则新增日志与审计要求

### 调整 12：统一记录范围与技术责任

以下正文用于后续纳入整体规则：

> **日志与审计规则**
>
> 0.1 必须实现必要的权限校验、同步重试、消息投递日志及审计记录，不因未建设管理查询页面而省略。
>
> 记录范围包括：
>
> 1. 权限相关记录：人员状态、角色及权限变更，鉴权失败和越权访问拦截。
> 2. 业务操作记录：重要业务数据的创建、修改、状态变化、负责人或协作关系调整，以及批量、导入、导出操作。
> 3. 配置变更记录：业务规则、Agent 配置、知识发布等配置和内容变更。
> 4. 集成与同步记录：同步执行结果、失败原因、自动及人工重试结果。
> 5. 消息投递记录：消息生成、发送、失败及重试结果。
> 6. AI 执行记录：能力调用、候选生成、人工确认后的写入结果、失败及重试结果。
>
> **相关的审计记录由技术人员查看分析并处理，具体的规则由技术定义。**
>
> 0.1 不单独建设系统审计查询、集成同步管理和消息投递日志管理页面。业务详情中的“日志记录”、异常事项和 AI 运行记录页面按各模块要求保留。

**调整原因：** 明确必须实现的记录范围及责任归属；日志字段、保存方式、技术查询、告警及处理细则由技术方案确定，不在产品页面中建设通用运维平台。

1. 销售和主管从 PC 菜单进入五类列表，均默认全部可见范围，且不存在越权数据。
2. 客户四个范围顺序、经营关系归属和列表去重符合规则。
3. 客户、线索、商机、任务没有隐含的默认状态或时间条件；任务默认全部可见正式任务；日报状态不限且默认当天。
4. 从列表进入详情再返回，Tab、筛选、排序和页码均恢复。
5. 同一模块不同数据范围使用相同展示字段，不按角色切换默认 Tab。
6. 管理分析、指标配置和专属导出不再出现在 0.1 导航、页面清单或交付验收中。
7. 客户关系网、经营关系、普通业务导出及业务日志仍保留。
8. 人员组织与权限为统一入口；业务配置子菜单完整且不包含指标配置、消息模板编辑器。
9. 技术管理查询页面移出后，权限校验、同步重试、消息投递日志、审计记录仍有技术实现责任。
10. H5 不增加本轮退出的分析、技术管理页面；保留已确认的轻量团队业务处理。

## 七、未决事项与不扩大范围的约束

| 项目 | 当前结论 |
|---|---|
| PC 任务默认时间 | 已确认不限制，默认展示全部可见正式任务 |
| 除客户以外，各模块具体 Tab 文案和完整集合 | 已确认全部默认、团队优先及个人／协作可切换方向；按模块已有对象关系落实，不强行每个模块都做相同四个 Tab |
| H5 团队快捷入口 | 已确认合并为一个“团队处理”入口，进入后可到任务、日报、线索、拜访源业务 |
| H5 是否同步采用 PC 的“默认全部” | 本轮默认范围来自 PC 结构讨论；如需改变 H5 已确认的个人优先结构，应另行明确 |
| 技术日志和审计细则 | 技术定义；本说明只固定必须实现的能力和记录范围 |
| 快捷入口携带条件、无来源详情返回默认列表 | 本文给出落地建议，具体入口映射在实施时核对 |

本轮不扩展管理员角色种类、业务字段权限、任务验收、日报退回或复杂数据治理审批。
