## 1. 目标与边界

线索先保留尚未结构化的销售信号，再由销售通过归属、跟进、无效判断或转换完成资格筛选。0.1 优先低门槛录入、明确归属、手工闭环和全程追溯。

**0.1 建设**

- H5／PC 单条创建、PC 固定模板批量导入和受控历史试迁移。
- 四种业务状态；指定负责人或指定池；分派、认领、转交、退回和手工回收。
- 按来源池计算的持有上限和池内取得负责人时产生的保护期。
- 销售活动、当前计划、正式任务和日程只读投影；整体事务转换、无效、重复指向和无效纠错。
- 受控导出、通知、审计、统一异常事项和客观运营指标。

**0.1 不做**

- 认领审批、主管代认领、自动分派、默认池回退、自动回收。
- 日／周领取上限、首次联系 SLA、活动自动续期、独立线索跟进记录和自动跟进任务。
- 线索合并、疑似重复关系、通用线索拆分、批量转换和部分成功转换。
- 公共占位客户、个人筛选视图保存、通用外部线索 API／实时同步和通用数据清洗工作台。

## 2. 创建、来源与状态

### 2.1 创建与查重

- 最低必填仅为原始内容和来源。客户、联系人、联系方式、候选业务线和外部记录 ID 均可空。
- 新建与普通字段编辑展示「联系人姓名」「联系人电话」并排输入；其中「联系人电话」复用线索级联系电话，不新增第二个电话字段。关联正式联系人后，两项由联系人主档自动带入并锁定；取消关联后可按线索级信息编辑。正式联系人主档仍是其联系方式的事实源。
- 原始内容永久保留且只读；通过补充说明、结构化字段修正或新来源记录纠正。结构化不足只做非阻断提示。
- 创建时必须明确保存为本人、直接分派或进入指定池；无负责人且无池时失败。新建统一为待处理，不产生保护期、任务或活动。
- 来源字典与系统记录来源（人工、批量导入、试迁移）分开。客户、联系人、线索业务相似和技术幂等分别检查。
- 只有技术重复强阻断；业务相似只提示。业务查重异常可降级并标记，技术幂等异常不得创建。外部数据不得静默覆盖销售已确认事实。

### 2.2 业务状态

| 状态 | 定义与条件 |
|---|---|
| 待处理 | 新建状态，尚未形成明确业务判断 |
| 跟进中 | 至少一条正式销售活动，下一步动作和下次跟进时间必填 |
| 已转化 | 通过显式整体事务产生新正式业务结果，终态只读 |
| 无效 | 人工确认不再继续，终态；只允许有权人员纠错撤销 |

待处理／跟进中均可直接转换或转无效。跟进中不回退待处理。活动可给建议但不自动改状态。暂不成熟的信号保留在当前活跃状态，使用下一步动作和下次跟进时间安排后续处理。已转化后的新需求及真实无效后的新信号均创建新线索并保留来源关系。

### 2.3 归属约束

- 活跃线索必须满足：当前负责人有值 XOR 当前池 ID 有值。
- 不建“未入池／在池待分配／在池已认领／已出池”枚举。当前池 ID 是是否在池的唯一当前事实，历史由流转记录表达。
- 进入已转化或无效后清空当前池和保护期，退出持有量统计。已有负责人不清空，继续展示和追溯，但不代表活跃经营责任；原本在池且无负责人的线索进入终态后允许两者都空。

## 3. 线索池、派领与保护

### 3.1 池配置

最小配置为编码、名称、状态、成员、是否允许主动认领、持有上限、保护开关／时长、退回开关／目标池。池状态仅启用、停止接收、停用。停止接收不进新线索，存量可继续处理；有存量不得直接停用。

分派、认领和池维护使用统一动作权限、数据范围和成员资格，不另建池内角色。修改配置立即影响后续动作，保留前后值，不建版本且不重算已发生事实。0.1 不建自动路由、池优先级、重叠命中、评分、随机或默认回退。

### 3.2 分派与认领

- 分派为有权人员将池内线索交给指定销售；认领为池成员本人取得线索。成功后写负责人、清当前池、保留来源池和取得方式，不改状态、不建任务。
- 分派校验动作权限、管理数据范围和对象状态；管理员（运营）按按钮权限操作且仍须通过正式资格和业务规则。池内分派目标销售必须是池成员；创建时直接分派和负责人直接转交不要求。
- 认领校验池成员、动作权限、数据范围、销售资格、来源池持有上限、池、负责人、状态和版本。全部校验和写入在同一原子事务内。
- 并发认领仅首个成功；其他人只看到“已被其他人认领”，不泄露新负责人。不建主管代认领，需要指定销售时使用分派。

### 3.3 持有上限与保护期

- 持有上限按来源池计算，只计当前由该销售负责、处于待处理或跟进中且从该池取得的线索。终态、已退回／回收／转交及从未过池的线索不计。
- 达上限后阻止新认领和该池新分派，不影响已有线索，不自动回收且不允许单次强制突破。
- 保护期只由池内分派或认领产生，从成功事务时间起算；未启用时截止时间为空，不用隐藏默认值。
- 销售活动不自动续期。主管或有延长权限的人员可显式延长并记录原新日期、原因、人和时间。
- 到期前一个自然日和到期时提醒；周期不足一日只做到期提醒。到期不清负责人、不改状态、不自动回收。

### 3.4 转交、退回与回收

- 转交为负责人 A 到 B，不经池。目标销售必须有效且有数据范围，不要求属于原池。成功后清保护期和当前持有量来源池，不受原池上限约束。
- 主动退回仅适用于当前负责人本人从池取得的活跃线索。原池必须允许退回，原因必填，目标池有效且可接收。从未过池的线索由有回收／转池权限的人处理。
- 手工回收要求回收权限、管理数据范围、原因和有效目标池。保护期内属强制回收，需对应权限和明确提示。
- 退回／回收成功后清负责人和保护期、写目标池；任一校验失败时原归属不变。
- 归属变化前提示未完成任务数量，但不阻断；不自动转派、完成、取消或修改任务。所有归属动作不改业务状态和销售事实。

## 4. 跟进、活动、任务与日程

- 销售活动表示已发生事实；正式任务表示未来待办；下一步动作和下次跟进时间是线索当前计划；状态历史表示业务判断变化。
- 正式活动至少有类型、发生时间、关联线索和真实结果／摘要。客户未识别时可只关联线索；正式拜访必须有真实客户。
- 保存活动更新最后跟进和时间线，可提示当前计划或状态，不自动改状态、续保护期、建任务或覆盖当前计划。活动建议经销售明确确认后才写入线索。
- 线索创建、归属变化、保存活动和修改计划均不自动创建正式任务。任务只由销售主动创建、主管正式指派或 Agent 候选经销售确认后产生。主管不代销售确认 Agent 候选。
- 任务完成不自动改线索。任务责任人默认取线索负责人，但两者独立；任一方责任人变更不自动改另一方。
- 下次跟进时间是统一日程唯一事实源。投影只读，不能改期、删除、取消、转任务、复制或企微反写。转交后向新负责人展示；退回、回收或进入终态后停止个人投影，原字段作历史保留。
- PC 线索详情的“记录销售活动”创建统一正式销售活动并关联当前线索；活跃线索在有活动创建权限且有数据范围时可操作，终态仅查看。保存后展示于活动表并更新最近跟进时间；下一步计划保持原值。页面同时展示有权查看的关联正式任务，不把计划当作任务。
- 销售活动修订保留原值、新值、原因、人和时间，不覆盖原始原件。

## 5. 转换、无效与来源关系

### 5.1 转换

- 待处理和跟进中均可直接转换，不强制提前存在销售活动。默认由当前负责人执行；他人需代转换权限和数据范围。
- 转换至少新建一条正式商机。只关联或新建客户、联系人而不创建商机，不构成线索转换。
- 不建占位客户。正式联系人和正式商机必须关联有效客户。整条转换可新建或复用多个客户；每条新商机在该商机下独立选择新建客户、关联已有客户，或复用本次转换中前面已新建的客户。同一客户可被多条商机复用。每条商机仍校验名称、唯一主业务线、销售场景、负责人、流程模板、权限和必填。
- 联系人也在每条新商机内选择，可不关联、关联已有联系人或新建联系人；建立联系人关系时只绑定该商机所选客户，不跨商机推断客户关系。
- 多个协同业务线可进同一商机；需独立负责人、流程、阶段、预计成交时间或销售目标时创建多条商机。
- 整条转换中的每条新商机单独选择一位主负责人，默认当前线索负责人；代转换时仍以当前线索负责人为默认值。候选人须有效且具备承接该商机的权限与数据范围，提交前逐条校验。新客户的初始经营关系主负责人另行选择，两者互不代填。商机与其主负责人、团队及首阶段任务须在同一整体事务内成立；任一条校验或创建失败则整条转换不生效。
- 提交前完整校验目标对象的查重、幂等、必填、权限和版本。产品层对用户只有整体成功或整体失败；任一必要步骤失败时原线索和可见目标对象都不变。跨系统使用技术补偿保证等效一致。
- 成功后线索进入已转化，清当前池和保护期，退出持有量；已有负责人保留用于展示和追溯。原线索、活动、任务、转换记录和目标链接永久保留。

### 5.2 无效、重复与纠错

- 待处理和跟进中可标无效。原因为无需求、联系不上、重复线索、信息错误、不属于目标业务、对方明确拒绝、竞品已签、其他；其他必须说明。无效不物理删除，不批量处理。
- 重复无效必须选一条有权保留线索并保存“重复于”，不迁移／合并数据。无权查看保留线索时不得完成重复处理，进统一异常事项且不泄露隐藏信息。
- 无效后清当前池和保护期，退出持有量；已有负责人保留展示和追溯。停止日程与保护提醒，原计划字段作历史保留。
- 只有主管或无效纠错权限人员可撤销误标无效，原因必填。优先恢复原状态、有效负责人或原池及原保护截止时间；原归属失效时必须先选新负责人或池。原保护已过期则恢复原日期并显示到期，不新增保护利益。

### 5.3 来源关系

0.1 删除普通线索拆分入口。多个成熟机会通过一次转换创建多条商机；已转化后新需求或商机衍生新需求时，新建线索并保存来源记录 ID 和来源类型。不建父子线索、关系图或任意关系网络。

## 6. 列表、详情与端职责

- H5 提供我的线索、本人有池成员及数据范围的线索池，以及本人及本团队范围内的主管/经理团队视角。0.1 不建协作线索或多负责人。
- H5 支持单条认领、分派、转交、退回、回收、状态动作、销售活动和转换，不导出。
- PC 提供我的／团队／负责人／池／状态／来源／候选业务线／保护／关键时间／终态筛选，不保存个人视图。支持单条及白名单批量归属动作、固定模板导入、导入结果和独立授权导出。
- 批量归属逐条预检和独立执行，允许部分成功并只重试失败项。不批量写活动、当前计划、业务状态或转换。
- 详情固定为原始与来源、结构化信息、状态与归属、当前计划、活动与任务、状态／池时间线、转换／重复／来源关系、AI 摘要及来源、审计九区。活跃线索的当前负责人可改普通字段；他人需编辑权限和数据范围；终态原则上只读。
- 有池成员资格的销售在认领前可查看线索完整信息；认领按钮、销售资格、上限、状态和并发仍逐项校验。
- 我的线索默认关注下次跟进逾期／即将到期、保护即将到期和长期未跟进，依据可见；池内按进池时间正序。
- PC 线索列表将编号、原始摘要、来源、来源记录、候选业务线、销售归属地区、当前负责人、当前池、业务状态、保护截止时间、下一步动作、下次跟进时间、最近活动时间分别成列。表格允许横向滚动，编号及操作保持易定位；不把不同业务字段堆在同一列。
- PC 原型额外提供一条标明“演示”的线索，详情可选择五种状态查看对应快照、可见动作、活动、任务、计划、历史与异常。切换只改变本页演示视图，不写正式线索状态、归属、审计或共享样例数据；演示记录不参与正式统计、批量操作和导出。
- 搜索与列表同权；无权线索不返回标题、摘要、数量或可推断信息。AI 摘要只读当前用户有权正式数据，显示截止时间和来源，不写回、不改状态／归属／排序／任务，证据不足时显示未知。

## 7. 批量导入与试迁移

- 固定模板每行必须有原始内容、来源，并且负责人与目标池有且仅有一个。允许批次统一指定或逐行填写。
- 上传后逐行预检，展示可导入／警告／失败；人工确认后逐行独立幂等创建。允许部分成功，只重试失败行，结果文件返回行号、线索编号或原因。
- 相同幂等键、相同来源系统＋相同非空外部记录 ID，或同批行重复执行不创建第二条。业务相似只警告，无权时不泄露已有对象。
- 历史系统只做盘点、字段映射和固定模板／受控脚本试迁移，不承诺全量切换。每次保留原始内容、时间、来源系统和批次标识。后续数据只追加快照或形成更新候选，不直接改正式线索。

## 8. 权限、敏感信息、通知与异常

- 所有动作同时校验按钮权限、三角色数据范围、业务状态、归属／池资格和对象版本。管理员（运营）可查看全部线索，操作仍按按钮及业务规则校验；Agent 服务身份取调用用户权限与服务身份能力的交集。
- 有权查看线索时，手机、微信、邮箱、原始内容及 AI 摘要均按完整业务信息展示；列表、搜索、查重和重复候选不另设字段范围或明文权限。
- 通知白名单为新负责人分派／转交、原负责人被回收、无效纠错恢复责任人、保护临期／到期、下次跟进、异步批量完成有失败项／失败和需人工处理异常。认领、主动退回和同步作业以页面结果为主。
- 通知失败不回滚业务或改状态；记录失败并幂等重试。站内消息保留深链，企微只推及时行动事件。
- 创建／渠道、关键字段、状态、归属、保护、无效／撤销、重复指向、转换、导入、导出、池和权限配置必须留痕。记录线索、动作、前后值、原因、人／服务身份、时间、渠道、请求／批次／幂等标识和结果。
- 0.1 不逐次审计普通查看／复制，但审计导出、批量和外部批量处理。
- 无权重复确认、终态留池、归属约束破坏、人员失效移交失败、外部数据冲突、导入持续失败和幂等异常进全系统异常事项，使用待处理、处理中、已完成、不采纳四态。异常事项不绕过线索权限、版本和业务校验，不增复杂审批、SLA升级、自动派单或讨论区。

## 9. 运营指标

0.1 只统计新增／来源数、当前状态分布、池内量、分派／认领及成功率、取得负责人至首次处理时长、转换数／率、无效及原因、退回／回收／转交、保护到期未处理、下次跟进逾期未处理和数据完整度等可验证事实。

- 新增按创建时间，转换按成功时间，当前状态按查询时点，流转按变更事件。重复仍计历史新增并另计重复无效；导入失败行不计。
- 首次处理按首个明确业务处理事件计算：跟进／无效路径要求正式销售活动与显式状态动作均完成；直接转换路径以整体转换成功事件为准，不额外强制销售活动。该时长只用于分析，不形成 SLA、催办、回收或绩效判断。
- 不建 AI 质量评分、销售排名、自动绩效或黑盒指标。汇总和明细使用同一指标版本、页面权限与数据范围，不另拆汇总／明细权限。

## 10. 核心验收

1. 只填原始内容、来源并明确负责人或池即可创建，原始内容不被覆盖。
2. 活跃线索负责人与当前池有且仅有一个，不存在池归属状态枚举。
3. 并发认领只一人成功，失败者不得推断新负责人。
4. 保护到期和活动不自动回收或续期，超额不自动处理已有线索。
5. 归属动作不改业务状态或任务；失败时原记录不变。
6. 活动、当前计划、正式任务和日程投影独立，任务完成不自动改线索。
7. 转换不强制活动，至少新建一条正式商机，用户侧整体成功／失败；正式商机必须关联有效客户，不建占位客户。
8. 重复用“无效＋重复于”；无权时进异常事项；纠错恢复原状态、可用归属和原保护日期。
9. 终态清当前池和保护期、退出持有量与提醒；已有负责人保留追溯但不代表活跃责任。
10. 导入逐行校验和幂等，允许部分成功；技术幂等异常行不得创建。
11. 列表、池摘要、搜索、AI 摘要和导出同权，无权用户不得推断隐藏数据。
12. H5／PC 共用同一线索对象、状态、归属和历史，批量入口不绕过单条校验。

## 11. 试点前产品配置

- 确认线索池编码、成员、持有上限、保护时长、退回开关与目标池。
- 确认来源字典初始值、导入模板与用户可见的批量上限。
- 确认转换率统计周期和分母口径；未经业务确认前不用于验收。
- 导出范围、通知时段及保留期限按已批准的业务和安全要求配置。跨系统补偿、幂等、告警与重试方案由研发设计。
