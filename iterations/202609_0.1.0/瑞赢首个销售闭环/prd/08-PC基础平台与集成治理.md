## 1. 目标与边界

PC 采用一个统一应用、一个工作区、一个首页和四个业务一级导航分组。系统管理与业务页面在同一导航体系中，不建设独立治理应用。

Agent 在 PC 0.1 不建自由输入和完整候选编辑器。06 只负责能力、来源、试点范围和预生成四页签业务配置；AI 运行记录、Run ID、失败、重试和日志治理由 05 定义业务链、08 统一承载，运维权限不扩大业务正文权限。

本模块分两层：

- 第一阶段：明确用户从 PC 进入哪些页面、如何查询和操作、批量／导入／导出如何执行，以及 H5/PC 如何保持同一事实；
- 第二阶段：补齐人员组织与权限、八类业务配置、异常事项、知识管理和 AI 运行记录与失败处理；必要的数据校验、同步重试、消息投递与审计记录在后台实现。

第二阶段不得通过配置重新开放已从 0.1 删除的功能，不得因外部系统失败改变瑞赢内部正式业务状态。

## 2. PC 首页、导航与全局能力

### 2.1 首页

所有人工用户登录后统一进入首页。首页是轻量导航页，不产生业务事实，只包括欢迎信息和固定快捷入口：

> 客户、线索、商机、任务、正式拜访、日报

快捷入口按当前页面权限过滤；管理员（运营） 可见全部入口。0.1 不支持用户自定义，不做最近访问、首页待办、指标、统计、Dashboard、业务卡片或拖拽布局。

业务深链直接进入目标页面并重新鉴权。

### 2.2 导航

一级导航：

1. 客户管理；
2. 销售管理；
3. 工作管理；
4. 系统管理。

右上角全局入口：全局搜索、消息、处理记录、用户头像。

系统管理二级导航：

- 人员组织与权限：一个入口，内部承接组织人员、角色和权限、停用与移交。
- 业务配置：字典管理、商机流程模板、线索池配置、全国公海规则、区域与业务线、任务规则、拜访规则、Agent 配置八个子菜单。
- 异常事项。
- 知识管理。
- AI 运行记录与失败处理。

具体页面清单见《00 产品结构与页面清单》。

## 3. 全局搜索

0.1 搜索对象为：

- 客户；
- 联系人；
- 线索；
- 商机；
- 任务；
- 正式拜访；
- 日报；
- 知识。

搜索只在当前用户有权数据范围内执行，不另建搜索权限模型。手机号、邮箱允许查询。每个对象只搜索预定义核心字段，不做全字段全文检索。

无权数据不返回结果、不展示数量、不展示摘要；进入详情时重新鉴权。

## 4. 列表、批量、导入、导出与处理记录

### 4.1 列表

0.1 不建设保存视图。列表只支持临时筛选、排序和列展示调整。

分页为 20、50、100 条。PC 客户、线索、商机、任务、日报从菜单进入默认全部可见范围；客户、线索、商机、任务状态与时间不限制，日报状态不限制、业务日期默认当天。客户四个范围顺序为全部／团队／我负责的／我协作的。返回列表时恢复原 Tab、筛选、排序和页码；菜单再次进入使用模块默认值，该信息是页面会话状态。

### 4.2 批量

- 支持当前页、跨页和全部筛选结果选择。
- 单次上限 100 条；超过 100 条禁止选择全部并提示缩小范围。
- 所有批量操作异步执行。
- 执行前服务端逐条预检，正式执行时再次逐条校验。
- 单条失败不影响其他记录；已成功项不得重复执行。
- 失败项可按原参数重试，重试时重新校验权限、状态、版本和业务规则。

### 4.3 导出

0.1 支持客户、联系人、线索、商机、销售活动、正式拜访、任务、日报的普通业务导出。

导出范围为当前选中记录或当前筛选结果；每个对象维护固定可导出字段清单，用户当次选择字段且不保存模板。

所有导出异步。文件有效期 7 天。发起时校验下钻／导出权限并冻结筛选和数据快照；文件生成后不因业务数据变化重新生成。下载时同时校验当前用户是创建人、仍有导出按钮权限及相应对象数据范围；已失权时禁止领取。

### 4.4 处理记录

处理记录统一承接批量、导入和导出，只展示本人发起的记录，保留 7 天。

展示类型、操作名称、对象、提交时间、总数、成功数、失败数、当前状态、结果／失败明细、文件下载和失败项重试。

处理记录用于查看执行进度与结果，不替代正式审计。

## 5. 三角色与人员准入

### 5.1 权限配置

0.1 只保留销售、销售主管/经理、管理员（运营）三个人工角色。销售看本人负责、本人协作、有成员资格的池内待认领线索完整信息及全国公海完整客户详情；主管/经理增加本团队业务记录；管理员（运营）看全部业务记录。页面、列表按功能列表权限控制，详情及创建、编辑、认领、分派、下钻、导出、配置发布、重试等按按钮权限控制。无字段范围、明文查看或按角色脱敏配置。

管理员角色授予和撤销由有权限的管理员执行，系统至少保留一名有效管理员，最后一名不可撤销。管理员操作仍须遵循按钮权限、对象状态与正式业务规则；密码、Token、密钥等系统凭证不得明文展示。

### 5.2 人员准入

公司用户中心是组织、人员和销售准入资格的事实源。瑞赢自动同步合格人员并授予销售角色，不以手工新增人员作为正常开通方式。工号缺失、冲突、格式异常或身份无法唯一匹配时，不创建正式人员，进入人员同步异常。恢复销售资格时只恢复人员有效状态和销售角色，不自动恢复历史主管/经理或管理员角色及业务责任。

### 5.3 企业微信认证

瑞赢只消费公司既有企微认证结果，不建设绑定、改绑或人工维护身份映射。未绑定、工号不一致、认证失效或认证失败时拒绝登录。管理员（运营）可按功能和按钮权限查看认证状态、同步结果和错误原因，但不能修改外部认证事实。

## 6. 调岗、停用与移交

团队成员关系、角色或销售资格等变化影响现有权限时：

1. 立即停止受影响的旧角色数据范围；
2. 保留未变化范围；
3. 生成权限待处理及受影响对象清单；
4. 不自动授予新角色；
5. 不自动完成业务移交。

姓名、手机号等普通资料变化不生成权限待处理。0.1 不建设 SLA、自动升级或自动催办。

人员停用、离职或销售资格失效时先立即停用，再处理移交，不能等待移交完成或为移交重新启用账号。

待移交清单按对象当前责任生成。接收人按对象类型分别选择，必须满足对象资格和权限；无合适接收人的保持待移交，不自动进入公海。执行支持部分成功和失败重试，成功项不重复，历史责任保留。

0.1 不建设临时代办或临时待办委托。

## 7. 配置发布模型

### 7.1 A 类简单配置

保存即生效：

- 字典；
- 线索池基础配置；
- 全国公海规则；
- 区域／业务线基础规则。

系统记录修改人、时间、前后值和历史操作，不建设草稿发布流程。

### 7.2 B 类规则配置

采用：

> 草稿 → 校验 → 发布 → 新版本

包括商机流程模板、任务规则和拜访规则。

发布必须原子成功；失败时保留上一有效版本，不出现部分新版本。发布前只校验必填、引用有效、无明确冲突和结构合法，不做复杂影响数量模拟。

新版本默认不静默修改已有业务事实；存量对象按原绑定版本解释。0.1 不做真正一键回滚，需要恢复旧版本时基于旧版本创建新草稿并发布成新版本。

## 8. 字典与商机自定义字段

字典值具备稳定编码、显示名称、排序、启停、适用范围和历史引用。已引用值不物理删除，不通过改名改变业务含义。停用值不可用于新业务，但历史数据正常展示。核心状态机不开放为自由字典。

商机自定义字段只开放文本、数字、日期、单选和多选。编码稳定，名称变化不改编码；不承载需要复杂字段级安全的敏感内容；字段不设置全局创建必填，流程模板可设置阶段推进前必填；被生效模板引用的字段不能直接停用。容量限制由技术评审确定。

## 9. 统一异常事项

统一异常事项状态：

> 待处理 → 处理中 → 已完成 / 不采纳

待处理默认无处理人。有权限用户点击“领取处理”后成为处理人并进入处理中；并发领取只允许一人成功。处理中可“退回待处理”，清空处理人。管理员（运营） 可重新指定处理人；处理人停用时自动退回待处理。

同一“对象 + 异常类型 + 目标字段／关系”同一时间只允许一条未完成事项，重复发现只补充发现信息。

异常事项不能直接修改正式业务事实，必须跳转源对象使用已有编辑动作，完成后再回到异常事项；0.1 不存在面向客户资料的治理事项或审批流程。

## 10. 数据校验与异常事项

客户、线索、商机等业务对象继续执行必要的必填、查重、映射和同步异常校验，并在源对象展示可处理提示。需要人工处理的业务问题进入统一异常事项。0.1 不建设独立数据质量概览、问题列表或质量规则管理页面；技术排障记录由技术人员通过受控工具查看和处理。

## 12. 知识管理

生命周期：

> 草稿 → 已发布 → 已停用

管理员（运营）按功能列表及编辑/发布按钮权限维护。编辑已发布文档时形成新草稿，重新发布后产生新版本，不直接覆盖正式版本。

只有已发布且当前用户处于发布范围内的知识进入全局搜索。发布范围支持全员、指定角色、指定业务线。

有查看权限即可下载；0.1 不单拆下载权限，只支持复制知识链接，打开链接重新鉴权。

停用后不进入普通搜索，也不作为 Agent 新回答来源。知识文档记录创建时间和创建人，并为后续每次修改、发布和停用追加操作日志，记录时间、操作人和修改说明；日志只追加，不提供旧版本回拨。Agent 只能引用当前正式已发布、调用用户有权访问的内容，并可追溯来源和当前版本。

用户反馈继续使用线下群，0.1 不建设知识反馈单。

## 13. 原件能力

0.1 不建设独立原件治理模块。原件直接依附销售活动和正式拜访，并在业务详情展示。

- 按当前业务权限查看和下载；
- 普通用户不能替换或删除正式业务证据；
- 管理员（运营） 可以查看、下载和处置；
- 保存来源、产生时间和关联对象等基础信息。

0.1 不建设保全中心、到期处置队列、复杂保留期限策略或单独菜单。

## 14. 外部系统与同步任务

外部系统只登记正式接入的系统，维护名称、环境、负责人、服务身份、能力范围、启停和最近健康状态。凭证不得明文展示。

0.1 不建设 API 管理平台、通用接口编排器、用户自定义接口或通用字段 Mapping。

同步任务状态：

> 待处理 → 处理中 → 成功 / 失败

记录来源系统、业务对象、方向、外部 ID、幂等标识、状态、执行时间、最后成功时间、失败原因和重试次数。

失败先自动重试，超过技术设定上限后进入失败并创建统一异常事项，技术人员按受控技术流程处理失败重试；同步失败不得改变源业务对象正式状态。

0.1 不建设通用对账平台；只在具体集成需要时提供检查差异和重新同步。冲突按该集成事实源规则处理，不静默覆盖。

解除映射只适用于确有瑞赢对象与外部对象映射的集成，人员同步和身份认证等事实源集成不允许解除映射。

## 15. 企业微信日程

0.1 只同步独立日程和正式拜访，任务不创建企微日程。

瑞赢业务事实优先，企微主要作为外部日程和提醒渠道。双向同步只开放白名单字段；企微不能修改任务截止时间、正式拜访状态或其他未授权事实。

企微取消或删除外部日程不能自动取消正式拜访，只更新映射和同步状态。

日程类对象允许解除旧映射、重新同步并创建新映射，旧映射保留历史。

若企微 API 不支持完整双向同步，能力降级为瑞赢到企微的单向同步，不展示不存在的双向能力。

## 16. 消息投递

站内消息是正式消息记录，企业微信是额外提醒渠道。只有产品白名单重要事件发送企微；用户可通过个人开关控制允许配置的站内消息与企微提醒，强制业务通知不受个人开关关闭。

消息模板由技术维护标题、正文、变量、适用事件和启停，不建设前台模板管理页面。业务事件发生时计算并保存接收人快照，后续人员变化不改写历史消息。

投递状态“待发送 / 发送中 / 成功 / 失败”与阅读状态“已读 / 未读”完全独立。

投递失败自动重试，超过上限创建消息投递失败异常事项，技术人员按受控技术流程处理失败重试；投递失败不得回滚业务事务。

0.1 不建设消息静默、消息合并、独立投递记录或模板管理页面、通用渠道降级或通用通知编排；个人通知开关按通知规则执行。

## 17. 审计

统一审计至少覆盖：

- 高影响业务操作和客户资料修改（含客户关系网、经营关系）；本期不产生客户合并与恢复动作；
- 权限、管理员（运营） 和数据范围变化；
- 配置发布；
- 批量、导入、导出；
- 重要系统治理动作。

审计字段至少包括操作时间、人、来源、对象类型和标识、动作、结果、关键前后值、失败原因及关联处理／同步／异常事项记录。来源区分 PC、H5、Agent 服务身份 和系统自动任务。

审计只记录本次实际变化的关键字段，不复制完整对象快照、大文本、文件或原件正文。

审计长期可追溯、只增不改且业务侧不可删除，不跟随处理记录 7 天清理。相关审计记录由技术人员查看分析并处理，具体规则由技术定义；业务详情“日志记录”仍按源业务权限查看。

0.1 不做前台系统审计查询页、审计导出、审计报表、访问行为分析或技术调用链分析。

## 18. 安全、降级与人工接管

- 权限或身份服务异常时不默认放大权限；可短时使用有有效期的最近一次有效缓存，否则拒绝访问。
- 高影响写操作具有请求唯一标识和幂等能力。
- 网络超时区分成功、失败、处理中和结果确认中，防止重复提交。
- 外部服务不是事实源时，其失败不阻断瑞赢内部可继续完成的核心业务。
- 自动重试超过上限后创建统一异常事项并人工接管。
- 配置发布必须全成或全不成，失败保留上一版本。
- 管理员（运营） 人工重试、重新同步或重新发布仍须通过正式规则和校验，不得直接修改底层状态。

## 19. 第二阶段验收矩阵

| 主题 | 核心链路 | 核心断言 |
|---|---|---|
| 新员工准入 | 用户中心 → 同步 → 人员 → 自动 销售 → 登录 | 不重复建人；异常身份不建正式人员 |
| 重复／乱序事件 | 新事件生效 → 旧事件到达 | 旧事件不覆盖新状态 |
| 调岗 | 变化 → 停旧范围 → 权限待处理 | 不自动授予新角色或移交 |
| 停用与移交 | 停用 → 禁止登录 → 待移交 → 分类接收 → 重试 | 先停用；历史责任保留 |
| 管理员（运营）角色 | 授予、撤销、最后一名撤销 | 有权限的管理员操作；最后一名必须拒绝 |
| 简单配置 | 修改 → 保存 | 立即生效并留历史 |
| 规则配置 | 草稿 → 校验 → 发布／失败 | 原子发布；上一版本继续有效 |
| 异常事项 | 并发领取、退回、重复发现 | 只一人领取；去重；退回清空处理人 |
| 数据质量 | 检测 → 异常 → 改源对象 → 重检 | 检测不直接修改事实 |
| 知识 | 草稿 → 发布 → 搜索 → 更新／停用 | 仅正式有权版本可搜索或被 Agent 引用 |
| 原件 | 活动／拜访详情查看与处置 | 权限继承业务对象 |
| 同步 | 失败 → 自动重试 → 异常 → 人工重试 | 幂等；不改变业务状态 |
| 企微日程 | 瑞赢日程／拜访 → 企微 → 外部删除 | 白名单同步；拜访不被自动取消 |
| 消息 | 业务事件 → 站内／企微 → 失败重试 | 渠道独立；不回滚业务 |
| 审计 | 权限、配置、批量、Agent服务身份 写入 | 来源清楚、不可篡改 |
| 安全降级 | 权限服务异常、网络超时、外部不可用 | 有效缓存或拒绝；幂等；核心业务可继续 |

所有关键能力至少覆盖正常成功、无权限、重复、乱序、并发、超时、结果未知、部分成功、自动／人工重试、外部不可用、人员停用、撤权、历史版本、异常去重及审计完整性。

高影响场景必须验证：

> 触发来源 → 系统处理 → 页面表现 → 正式事实变化 → 失败恢复 → 异常事项（需要时）→ 审计

不能只以页面出现成功提示作为验收完成。

## 20. 0.1 明确不建设

- 临时代办；
- 独立原件治理中心或保全中心；
- 通用集成编排器、字段映射平台或对账平台；
- 数据质量自由规则设计器；
- 配置审批流、复杂影响模拟或真正一键回滚；
- SLA 或自动升级体系；
- 消息静默、合并、个人偏好或通用渠道降级；
- 审计导出、自由报表或技术调用链分析平台。

## 21. 技术评审待定

- 自动重试次数、间隔和退避策略；
- 权限缓存有效期；
- 商机自定义字段容量；
- 企微日程实际 API 能力和字段白名单；
- 审计、同步及消息记录的物理保存与归档期限；
- 密钥托管、轮换和脱敏实现。
