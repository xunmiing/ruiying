## 1. 总体结构

### 1.1 H5

企业微信 H5 以销售个人执行为主，主管／经理通过一个“团队处理”快捷入口进入线索、任务、日报、拜访的源业务页面，继续承接日常查看、记录、跟进、确认和闭环。

H5 默认进入 M01 工作台，底部五个主入口为工作台、任务、日程、互动、知识库；互动页同页切换时间线、本人拜访、本人日报，其他个人拜访／日报入口定位到对应 Tab。M19 浮动助手在有权页面唤起，M20 与完整 AI 首页使用全屏二级页。M00 导读及 M26 功能全景图只服务原型演示／评审，不是生产系统必建页面。M 编号是原型结构编号，不要求每个编号对应一个独立 HTML 文件。客户、联系人、线索、商机从 M01 底部快捷入口进入全屏二级流程；主管从工作台唯一“团队处理”入口进入四类源队列，使用同一个 H5。H5 不设全局搜索页，AI 查询结果和业务深链进入各源对象；各业务列表仍可按本对象检索。

Agent 在 H5 完整提供：AI 首页、沟通整理、候选确认、AI 待确认（当前／历史待处理／写入失败）、会议任务确认、对象 AI、日报和主管关注。

H5 全局悬浮区在现有 AI 助手按钮上方增加带文字的“速记”按钮，点击直达个人速记全屏页；键盘打开时收起悬浮按钮，速记页不重复显示速记入口。速记页默认语音，可切文本录入及查看本人历史；它不是底部主入口，也不属于 AI 候选历史。

### 1.2 PC

PC 采用：

> 一个统一应用 + 一个工作区 + 一个首页 + 四个业务一级导航分组

Agent 在 PC 保持轻量：业务候选处理仍以 H5 为主；AI 运行记录和失败治理归 05/08；06 只提供一个 Agent 配置页面，以能力、来源、试点范围和预生成四个页签维护业务开关及范围，不建设 PC 自由输入和完整候选编辑器。

所有人工用户登录后统一进入首页。业务页面、治理页面和配置页面属于同一导航体系，不形成新的权限层级。PC 优先方便主管／经理处理团队业务，也支持其本人销售工作；销售同样可以使用 PC。

四个业务一级导航为：

1. 客户管理；
2. 销售管理；
3. 工作管理；
4. 系统管理。

PC 与 H5 共用业务对象 ID、业务状态、权限和数据范围、版本控制及正式业务事实。业务深链不经过首页，直接打开目标页面并重新鉴权。

PC 评审原型使用固定演示账号连续走查，不在页面内切换评审身份。每页提供默认收起的右侧「页面说明」，集中介绍功能、三角色正式数据范围及按钮权限；具体字段和操作规则以就近黄色短标签打开说明。演示线索、演示商机等样例须明确标识，不进入正式列表计数、批量或导出。以上是原型展示约定，正式系统仍以权限模型、对象状态和服务端校验执行操作。

## 2. PC 首页与全局入口

### 2.1 首页

首页是轻量导航页，不是业务对象，不产生业务事实。

0.1 只包含：

- 姓名、日期等基础欢迎信息；
- 固定快捷入口：客户、线索、商机、任务、销售活动、日报。PC 销售活动入口汇总普通活动与正式拜访。

所有用户使用同一套快捷入口，并按当前页面权限过滤；管理员（运营）按配置的功能列表看到快捷入口。

0.1 不支持用户增加、删除或排序快捷入口；不建设最近访问、待办聚合、经营指标、业务统计、Dashboard、个性化数据卡片或拖拽布局。

### 2.2 右上角全局入口

- 全局搜索；
- 消息；
- 处理记录；
- 用户头像。

## 7. 列表与详情通则

列表统一结构：

> 页面标题 → 范围 Tab（需要时）→ 筛选区 → 操作区 → 表格 → 分页

分页支持 20、50、100 条。从详情返回时恢复来源页面、原 Tab、筛选、排序和页码；这是页面会话状态，不是保存视图。

PC 客户、线索、商机、任务、日报从菜单进入时默认“全部可见范围”。客户、线索、商机和任务的状态与时间默认不限制；日报状态默认不限制、时间默认当天。数据范围、状态与时间是独立条件。客户范围顺序固定为“全部／团队／我负责的／我协作的”；同一模块切换范围不另换展示字段。菜单再次进入使用模块默认值，详情返回恢复列表会话。

0.1 不建设个人或共享保存视图。列表可临时筛选、排序和调整列。

一个详情页最多 3 个主按钮，低频动作收入“更多”。按钮根据当前权限和对象状态动态展示；不可操作时优先不展示。一般操作成功后留在当前详情并刷新，对象不可用进入统一状态。

## 8. 批量、导入、导出与处理记录

- 批量支持当前页勾选、跨页勾选、选择全部筛选结果。
- 单次批量上限 100 条；筛选结果超过 100 条时必须缩小范围，不静默截取。
- 批量统一异步，执行前预检，正式执行时逐条重检；单条失败不影响其他记录。
- 已成功项不得重复执行；失败项可按原参数重试并重新校验权限、状态和规则。
- 导出支持客户、联系人、线索、商机、销售活动、正式拜访、任务、日报。
- 业务对象导出范围为当前选中记录或当前筛选结果，字段来自对象固定可导出清单，用户当次选择且不保存模板。
- 导出文件与前台处理记录均保留 7 天。
- 下载时校验当前登录用户是该导出记录创建人；处理记录只展示本人发起的记录。
- 处理记录不替代正式审计。

## 9. 页面跳转与跨端一致性

- 对象名称或编号进入详情，每次重新鉴权。
- 详情返回原来源上下文，不强制回到对象列表。
- 消息和深链绕过首页直接进入目标。
- 本期不提供客户合并及恢复，系统没有历史已合并客户数据。
- 对象失权进入无权限页；对象不可用进入统一不可用状态。
- 版本冲突不允许后提交静默覆盖前提交。
- H5 与 PC 使用同一对象 ID、状态、权限、数据范围、版本控制和业务事实。
- PC 修改后不要求 H5 实时推送，H5 刷新或重新进入时读取最新事实。

### 6.25 统一 PC 导航、角色菜单与旧原型深链差异

> **依据**：统一身份、角色能力与本迭代最终页面结构｜**原型**：现有 HTML 尚未同步

生产产品使用统一企业身份。企业微信 H5 负责高频执行；PC 是一个统一应用和工作区，所有人工用户登录进入轻量首页，业务、配置与治理页面统一纳入四个业务一级导航。菜单由当前用户的页面权限过滤，任何入口均重新鉴权。`index.html`、`manager.html`、`admin.html` 的文件拆分只是旧静态原型组织方式，不代表生产工作区；其中 `manager.html`／`admin.html` 的路由表仅保留作历史差异证据，不再作为目标页面、导航或 P0 跳转验收依据。

| 场景 | 产品行为 |
|---|---|
| 登录后进入 | PC 用户进入同一首页；H5 按高频业务入口进入，不因销售、主管或管理员角色跳到不同应用 |
| 菜单与入口 | 四个 PC 业务一级导航固定；具体页面、快捷入口和按钮按功能列表与按钮权限展示，访问目标页面时重新核验当前数据范围 |
| 对象跳转 | 从搜索、消息、任务、客户或商机等入口打开目标对象；保留来源与必要筛选，返回时回到来源视图 |
| 无权限或对象变化 | 目标已失权时展示无权限态；对象已关闭或被移交时展示当前可见结果和下一步提示，不显示过期的旧详情 |
| 跨端一致性 | H5 与 PC 查看同一业务对象、状态及修改历史；刷新或重新进入时读取最新正式事实 |

旧静态原型的多文件路由仅供评审差异核对，不作为产品导航、权限或跳转方式的要求。
