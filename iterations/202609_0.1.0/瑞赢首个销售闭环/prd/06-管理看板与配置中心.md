# 06 业务配置模块 PRD

> 版本：V1.4｜日期：2026-10-12｜状态：0.1 轻量化口径
> 上位文档：../prd.md。01～05 定义源业务对象和规则；07 定义正式权限；08 定义技术运行、失败恢复及日志责任。
> 本轮调整：PC 管理分析、指标趋势与下钻、指标定义与版本、管理分析专属导出整体移出 0.1。本模块只承担业务配置。

## 1. 模块定位与页面范围

系统管理的“业务配置”展开为八个子菜单：字典管理、商机流程模板、线索池配置、全国公海规则、区域与业务线、任务规则、拜访规则、Agent 配置。只有管理员（运营）拥有配置治理操作权限；主管／经理在有权限时可只读查看本团队适用的拜访生效规则。所有动作仍按功能列表、按钮权限、对象状态和服务端规则校验。

| 子菜单 | 配置性质 | 页面责任 |
|---|---|---|
| 字典管理 | A 类 | 维护业务选项的编码、名称、顺序与启停 |
| 商机流程模板 | B 类 | 配置阶段、门槛、阶段任务和停滞规则 |
| 线索池配置 | A 类 | 配置成员、认领、持有、保护和回收规则 |
| 全国公海规则 | A 类固定对象 | 配置资格、持有上限、保护与回收规则 |
| 区域与业务线 | A 类 | 维护经营区域、业务线及外部映射 |
| 任务规则 | B 类 | 配置生成、截止和提醒，不配置验收流程 |
| 拜访规则 | B 类 | 配置适用范围、签到凭证与异常规则 |
| Agent 配置 | 保存即生效 | 能力、来源、试点范围、预生成四个页签 |

配置只能实现 01～05 已确认的业务规则，不得重新定义对象、状态或门槛。商机自定义字段配置、指标配置和分析看板不进入本期业务配置菜单。H5 不建设这些配置页面。

## 2. 配置页面统一规则


结构统一为：

> **基本信息 → 当前配置 → 引用关系 → 修改记录／版本历史。**

- 支持关键词、状态和必要业务筛选；详情默认只读，从列表或详情进入编辑。
- 只有可重复对象提供新建；只有有实际复用价值时提供复制。
- 原则上不物理删除；停用前校验引用；并发保存或发布不得静默覆盖。
- A 类展示修改历史，B 类展示版本历史；发布、停用、恢复等高影响操作要求原因。
- 全国公海是唯一固定对象，不提供新建、复制、删除和停用；Agent 是固定配置页，不新建 Agent 对象。

### 2.1 A 类配置

字典、线索池、全国公海规则、区域与业务线规则采用保存即生效：

- 保存前校验，失败时原值不变且不允许部分字段生效。
- 普通保存不强制原因；高影响停用、恢复或纠错要求原因。
- 已引用配置不得物理删除；停用只阻止新的引用，不破坏历史事实。
- A 类修改只影响之后的新判断、新选择和新业务处理，不静默改写历史；0.1 不做一键历史回滚。

### 2.2 B 类配置

PC 配置页以“当前规则及操作”优先：全国公海规则在同页展示认领、分派、持有上限、保护期及保存确认，保存后的新认领或分派按最新规则判断，历史经营关系不回写；任务规则以版本列表选择详情，已发布版本只读，复制为草稿后编辑、校验、发布，已有进行中草稿时复用该草稿；拜访规则列表显示状态与适用范围，支持进入新建、详情及版本操作。页面说明集中承载权限、版本、并发和生效边界；字段旁用黄色标签解释具体规则。HTML 可走查保存和状态变化，服务端并发与鉴权仍按正式实现验收。

流程模板、任务规则和拜访规则采用：

> **草稿 → 校验 → 原子发布 → 新版本。**

- 已发布版本不可直接编辑；修改生成新草稿，同一对象只保留一个进行中草稿。
- 0.1 只支持立即发布，不建设预约、待生效、排队或取消预约；发布成功时间即生效时间。
- 发布失败时旧版本继续生效且草稿保留；并发发布必须阻断，历史版本只读。
- 回退时基于历史版本生成新草稿并再次发布，不做一键回滚。

版本绑定点：流程模板在商机首次绑定时固定；阶段规则和停滞阈值跟随该流程版本；任务规则在任务生成时固定；拜访规则在拜访记录／任务创建时固定。0.1 不提供新版发布后的存量批量迁移。

拜访规则按结构化的业务线、经营区域、具体人员配置适用范围；同一维度可多选，跨维度同时配置时须全部命中。命中优先级为具体人员、业务线与区域组合、单维业务线或区域、全局规则；同级命中取最近发布版本，仍同时时按稳定规则编码排序。拜访计划创建时保存命中的规则 ID、版本和参数快照；人员调岗和规则发布不重算已有拜访。未命中生效规则时只记录签到／签退事实，不产生无依据的阈值异常。签退可在异地完成，签到与签退之间的时间间隔只作异常提示，不作为持续在场证明。

管理员（运营）可按功能列表和按钮权限查看、编辑拜访规则草稿并发布或停用；主管/经理只读查看当前团队适用的生效规则，不展示草稿及历史配置。

### 2.3 停用引用处理

停用只阻止新引用，已绑定存量继续按原版本运行；如果其他当前生效配置强依赖目标配置，则阻止停用并展示依赖关系。

| 配置 | 停用后行为 |
|---|---|
| 字典项 | 新数据不可选，历史继续展示 |
| 流程模板 | 新商机不可绑定，存量继续运行 |
| 任务规则 | 不生成新任务，已有任务继续 |
| 拜访规则 | 新拜访不绑定，已有拜访继续 |
| 区域／业务线映射 | 禁止新增使用，历史保留 |
| 线索池 | 停用前必须处理无法承接的存量线索 |

## 3. 七类业务配置字段框架

| 页面 | 字段框架 |
|---|---|
| 字典 | 字典编码、名称、适用范围、字典项编码／名称、排序、启用状态 |
| 流程模板 | 模板编码、名称、匹配范围／键、阶段、门槛、阶段任务、停滞阈值、状态、版本 |
| 线索池 | 池编码、名称、适用范围、成员范围、认领、持有、保护、退回／回收参数、状态 |
| 全国公海规则 | 认领资格、持有上限、保护规则、主管回收规则 |
| 区域与业务线规则 | 外部稳定编码、名称、CRM 映射、适用范围、启用状态 |
| 任务规则 | 规则编码、名称、适用范围、任务来源／属性、截止、提醒、状态、版本 |
| 拜访规则 | 规则编码、名称、适用范围、真实性参数、凭证参数、其他 04 已确认规则、状态、版本 |

每个字段在详细规格中继续补齐数据类型、必填、默认值、唯一性、可编辑性、引用关系、可停用条件和权限，但不得改变本 PRD 的对象及生效模型。

线索池页面按“基本信息 → 适用范围 → 成员 → 认领与持有 → 保护 → 退回／回收”；全国公海页面按“认领资格 → 持有上限 → 保护规则 → 主管回收”。具体字段和值由 01/02 提供，06 不建设万能规则编辑器。


## 4. Agent 配置


Agent 配置是单页面四页签，采用保存即生效，不走完整 B 类发布。06 只负责“哪些能力、哪些来源、对哪些人、何时运行”。Prompt、模型、Workflow、Coze 地址、超时、技术重试和模型日志期限不属于 06；人工确认原则不可关闭。

### 4.1 能力与来源依赖

每项能力维护必需来源、可选来源、试点范围要求和是否需要预生成任务。必需来源缺失时不得启用；关闭来源前反查已启用能力，若为必需来源则阻止关闭并提示先停用能力，不静默联动关闭。可选来源缺失时允许运行但不使用对应信息。

扩大试点范围前预览新增去重人员数和因权限／数据条件无法启用人数；缩小范围立即生效。高影响范围调整要求原因，能力关闭只停止后续生成，不删除历史正式事实。

### 4.2 预生成

0.1 固定三项预生成任务，每项一个执行时间，并维护历史待处理时间；具体能力由 05 定义，不允许业务人员自由新增调度任务。

- 使用统一业务时区，精度到小时:分钟；修改从下一次调度生效。
- 同一人员、同一业务日期必须幂等。
- 当日因系统故障错过时间，恢复后自动补跑一次；跨到下一业务日默认不补历史候选。
- 人工补跑、失败重试和任务日志归 08，06 不建设操作入口。


## 5. 权限、留痕与失败恢复

业务配置页面按三角色功能列表权限开放，保存、编辑、校验、发布、停用和恢复按按钮权限校验；管理员操作仍遵守引用、版本和并发规则。配置动作记录操作人、时间、对象、关键前后值、原因、结果和版本；相关审计记录由技术人员查看分析并处理，具体日志规则由技术定义。普通打开、查询和筛选不做业务级审计。

强制原因范围：B 类发布、停用与恢复，Agent 扩大试点范围或关闭有业务影响的能力，高影响 A 类停用及已产生业务影响的特殊恢复／纠错。普通 A 类字段编辑、排序、草稿保存及 Agent 预生成时间普通调整不强制原因。

| 异常 | 处理 |
|---|---|
| A 类保存失败 | 原值保持不变，不部分生效 |
| B 类发布失败 | 旧版本继续运行，草稿保留 |
| 并发修改或发布 | 阻止静默覆盖，刷新后重新校验 |
| 引用失效 | 阻止破坏性修改并展示依赖 |
| 失权深链 | 拒绝访问，不展示业务摘要 |
| 配置停用 | 阻止新引用，已有业务继续按原版本解释 |

B 类发布失败通知发布人；普通 A 类保存只记日志。跨页面异常处理归 08，异常事项入口归源业务处理链。

## 6. 试点前回填


以下只影响正式启用，不改变通用产品规则：

- 线索池：持有上限、领取／退回条件和回收规则。
- 全国公海：保护期、认领资格、持有上限及 01 已确定参数。
- 商机：各阶段停滞阈值、有效推进事件白名单、正式模板和阶段任务。
- 任务：提醒窗口和正式任务规则。
- 拜访：真实性参数和正式拜访规则。
- 区域与业务线：组织范围、启用状态、外部事实源和 CRM 映射。
- Agent：试点范围、三项预生成时间、历史待处理时间及能力—来源依赖矩阵。


## 7. 验收重点

逐页检查权限、字段与引用、A 类保存即生效、B 类原子发布、并发冲突、失败恢复、停用后历史解释和 Agent 配置的来源依赖。任务规则页面不得出现任务验收参数。业务配置导航必须有八个子菜单；管理分析、指标定义与版本不得作为本期配置或验收对象。
